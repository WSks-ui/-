# 详情形态的逐面光照

日期：2026-10-16。对应更新后的 `DEV_GUIDE_NEXT.md` 优先级 2c。实现沿用当前模拟器已验证的原生 ArkUI Canvas，将新光照和几何规则接入实际运行路径；没有重新启用已出现 EGL 崩溃的 ArkWeb 控件。

## 实际改动

`SiteObjectGeometry.ts` 同时提供原始多边形和 GPU 使用的三角索引。软件绘制对整个多边形计算一次法线、填色与描边，不再显示三角剖分的对角线。网格先完成所有顶点，再生成面；回转轴上的重复顶点合并为有效三角面，避免零法线和读到尚未创建的下一圈顶点。

`SiteObjectRaster.ts` 是不依赖平台的投影与光照规则，`SiteObjectCanvas.ets` 负责实际 Canvas API 调用：

1. 绕 X / Y 轴旋转顶点，两条旋转后的面边叉乘并归一化，得到逐面法线。
2. 主光方向为归一化后的 `(1.2, 2.0, 1.5)`，亮度为 `0.30 + 0.55 × max(0, n·L)`。
3. 定向高光为 `0.28 × max(0, n·H)^22`，方向为归一化后的 `(0.4, 0.8, 1.0)`。这是任务书指定的 Blinn-Phong 形式近似，亮斑由几何法线产生；不是物理釉面或金属材质。
4. 按屏幕坐标的面绕序剔除背面，然后按平均深度从远到近绘制。当前相机在 +Z，屏幕 Y 向下，正面绕序为负，符号与任务书 HTML 示例的坐标约定不同。
5. 阴影在模型之前绘制，径向渐变压成椭圆，并按自动取景后的底边定位。边线为 0.5 Canvas 单位的半透明线，浅色暗边、深色亮边；它们属于几何示意，与 HDS 系统材质无关。

## 五种可体验形态

| 形态 | 本轮几何与受光 |
|---|---|
| 陶器 | 16 段旋成体，主体轮廓保留 10 个纵向区间，另外保留陶口与内腔；插入三道窄纹带，纹带与器身共用表面，不叠加共面网格 |
| 城台 | 三层递减方台，顶面和两侧各用真实面法线受光 |
| 城垣 | 24 段、有厚度的环形截面，外壁 / 内壁反向，顶部与底部封闭，替换此前的圆管环 |
| 层塔 | 五层八角斜面，各层收分和高度有所区别，并有顶部尖锥 |
| 封土 | 18 段、10 个弧面区间的半球形示意，明暗与高光随面方向变化 |

这些纹带和形态均为应用内的程序化装饰，不对应具体遗址形制、考古纹样或文物复原。页面的几何示意说明与文化初稿状态继续保留。窑址没有当前目录条目，仅保留已有几何规则的本地验证。

`SiteObject3D` 改为接收整个 `site: HeritageSite`，由组件读取类型与档案主色；`SiteDetail` 已同步调用。主题从 `surface_soft` 语义资源读取，不能用沉浸材质开关 `lightEnabled` 推断深色。左右旋转、拖动、复位、自动 / 暂停、减少动态与离开页面释放等操作继续沿用原有生命周期。

## 剔除与性能的范围

初始视角下，五种形态剔除的多边形比例约为 48%—58.6%，具体数量见 [面数量](design/lighting/culling-counts.json)。这是纯数学计算的绘制面数量，不是设备帧率或耗时提升；本轮没有把任务书中的“效率提升约 40%”作为实测结论。

当前仍是按面深度排序的软件绘制，没有像素深度缓冲、纹理或真实阴影映射。支持设备上的 `Component3D` 路径继续保留，但其 PBR 材质不等于本轮的软件着色，GPU 可见效果仍须在支持设备上另行验收。
