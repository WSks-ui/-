# 五城原生离线演示

更新日期：2026-10-23。脚本：[tools/roaming-demo.py](../tools/roaming-demo.py)。目标为当前 HarmonyOS 7 / API 26 原生工程，使用 Python 标准库与 SDK 的 HDC，直接读取设备 `uitest` 布局并操作 ArkUI。**脚本只在必填的 Debug 独立测试库中运行。**

**当前状态：M12 完整单端原生演示已实际走通。** 主线程于 2026-10-23 在手机 `127.0.0.1:5555` 使用独立库 `yunheji_test_ui_roaming_demo_m12_r3` 执行本脚本，最终 [原始结果](design/roaming/demo/result.json) 为 `completed`，共 **383 条真实 HDC 命令**。原生五城选择、开封三条线索、空白感想、真实输入、确认保存、长卷顶部最近页、原文与出处、系统分享展示与取消均完成。主包 M12 为 7629427 字节，SHA-256 为 `FD6E7B3C89A155528FC9166B012AF96DB029DFE8AA379EC4ED669FBECD517094`。原图、布局、对比和命令审核信息见 [完整证据图集](design/roaming/demo/README.md)。

M11 的页首进度回读失败，以及 M12 前次的键盘系统栏误拦截均继续保留，详见[失败历史](design/roaming/demo/README.md#保留的前次失败)。修复保持真实布局定位、精确文字断言和键盘窗口关联检查，账号页、隐私同意、未知应用及未知对话框继续阻断。实际成功没有覆盖前次失败，脚本完成状态也不替代 Hypium 的 `Pass / Failure / Error` 摘要或工程的构建结果。

本次全程只断开该手机访问任务账号服务的 `tcp:18443` HDC reverse，**未关闭设备全部网络**。另外对同一独立库做系统分享取消专项，整个 Preferences 前后均为 **6705 字节**、逐字节一致，SHA-256 均为 `D215232CB8E443D887D43E320FC6321473BF761C81FB092056FBA18D1D283A86`，见[安全对比 JSON](design/roaming/demo/share-cancel-comparison.json)。本轮未执行双端同步或向外部接收人发送。

旧的 [DEMO.md](DEMO.md)、[账号同步说明](ACCOUNT_SYNC.md) 与其他演示工具继续保留。本脚本专门走五城漫游的新路径。

## 1. 实际操作路径

脚本依次完成这些原生操作：

1. 从漫游首页依次选择三门峡、洛阳、郑州、开封、濮阳的五个题签，逐一回读篇章标题，再选择开封。
2. 核对开封为 `0 / 3`，拖动水线滑条找到街与河的交会，选择片段并确认第一条线索。
3. 拖动时间观察窗，选择桥的层次并确认第二条线索。
4. 打开灯事的读城小笺，选择“愿灯火可亲”，点击“点亮这盏灯”，再确认第三条线索。
5. 打开“我的记忆笺”，先保存感想框**确实为空**的原生画面，再通过原生输入命令写入一段带本轮编号的公开演示感想。资料依据留在摘录区域，感想不由资料正文自动填充。
6. 逐字回读输入结果，点击“确认，存入我的记忆”，等待“这一页已在本机保存。”。
7. 打开“我的黄河长卷”，从顶部“最近留下”进入刚保存的一页，核对亲笔正文、灯事文化摘录、来源标题和完整网址。
8. 传入 `--share` 时，打开真实系统分享面板并取消，回读同一页正文。不会选择联系人、华为分享、复制、图库、打印或中转站操作。

所有数据由真实 UI 的保存动作生成。脚本不注入 Preferences、不写数据库、不读取旧的 `accounts.json`、不生成同步成功时间，也不安装、卸载或清空应用。

## 2. 运行前准备

- 安装 Python 3.10 或更新版本，准备当前工程的主包并安装到目标设备。本脚本不构建或安装 HAP。
- 准备 SDK 自带 HDC，确保目标设备已连接、解锁，`uitest dumpLayout`、`uiInput`、`screenCap` 可以使用。`--phone` 是 HDC target ID，脚本将所有设备命令限定到这个目标。
- 先手动在主演示设备打开云河纪的**漫游首页**，或没有输入账号、密码的**空白登录页**。脚本会拒绝从章节、编辑、个人设置、非空登录表单或其他应用强行恢复路径。
- 提前用人工方式完成设备输入法的首次初始化与所需隐私选择。脚本发现输入法同意页会停止，不替人点击协议。新模拟器建议先在系统应用中确认中文可输入，再回到云河纪。
- 每轮使用新的独立测试库名。演示工作区必须没有亲笔记忆，开封必须为 `0 / 3`；已有内容不会被删除。其他城市可以有真实探索进度。
- 运行期间保持设备朝向与窗口状态稳定，暂停其他脚本、测试和人工点击。系统弹窗、页面变化或控件不唯一都会停止本轮。

本轮已验证手机到任务账号服务的反向端口不可用时，仍可完成上述单端路径。脚本本身不切换网络、不要求启动账号或 AI 服务；“本机保存”表示本机确认保存及原文回读，不代表设备全部网络不可用或已经完成账号同步。

## 3. 命令示例

在仓库根目录的 PowerShell 中准备 HDC 路径与设备 ID。以下只使用自行配置的环境变量，没有开发者目录依赖：

```powershell
$demoHdc = Join-Path $env:DEVECO_HOME 'sdk\default\openharmony\toolchains\hdc.exe'
& $demoHdc list targets
python .\tools\roaming-demo.py --help
```

把实际 target ID 写入变量。库名每轮更换，保留小写字母、数字和下划线：

```powershell
$demoPhone = '<手机的 HDC target ID>'
python .\tools\roaming-demo.py `
  --hdc $demoHdc `
  --phone $demoPhone `
  --isolated yunheji_test_ui_roaming_20261023_a `
  --pace 1.5 `
  --share
```

`--isolated` 只接受 `yunheji_test_ui_[a-z0-9_]{1,80}`。脚本通过目标设备的 `bm dump -n com.yunheji.archive` 同时核对 `debug: true` 和 `appProvisionType: "debug"`；缺少、未知或冲突时停止。核对后才执行应用强停和携带 `yunhejiTestStore` 的冷启动，因为热启动 `onNewWant` 不会切换当前库。Release 不接受测试库 Want，不能用猜测包名或待安装 HAP 代替这个检查。

隔离库冷启动后可能出现空白登录页。脚本只会等本机档案准备完成，再点击原生“离线浏览本机档案”；该页面不保存截图或布局，已有账号、密码输入会直接阻止运行。

`--isolated` 为必填参数，缺少时在参数解析阶段退出。脚本不提供正式用户库运行入口，前台工作区仅用于确认没有未保存草稿或凭据，不在冷启动隔离前执行写操作。

可选参数：

| 参数 | 用途 |
| --- | --- |
| `--hdc` | 必填，HDC 文件路径或 PATH 中的命令名称 |
| `--phone` | 必填，唯一被脚本控制的设备 |
| `--tablet` | 可选，记入结果的人工接续设备 ID，不向这台设备发送命令 |
| `--isolated` | 必填，Debug 独立测试库名 |
| `--pace` | 每次交互后停留秒数，默认 `1.5`，接受 `0`—`30` |
| `--share` | 可选，展示真实系统分享面板并取消 |
| `--output` | 可选，新建证据目录；已有目录会被拒绝，防止覆盖旧结果 |
| `--stop-file` | 可选，立即停止用的文件路径；默认 `<本轮证据目录>/STOP` |

脚本另提供独立的离线夹具模式，显式传入已经脱敏的完整 `uitest dumpLayout` JSON。该模式不接受设备参数、不构造 HDC、不需要现有 `.local` 配置：

```powershell
python .\tools\roaming-demo.py --check-layout '<已脱敏的完整键盘布局.json>'
```

它检查真实感想输入布局可通过、已初始化键盘画布及系统栏窗口关联，并在内存副本中检查未知大面积系统窗、错误窗口编号、任意输入法名称应用、焦点丢失、隐私同意、未知对话框、未知应用、账号输入与个人设置页仍被阻断。成功输出 `status: "passed"` 和 `deviceCommandsSent: 0`；此结果只证明布局识别，不表示设备输入或保存完成。

默认输出是仓库下 `.local/roaming-demo/<时间与随机编号>/`。这是**本轮新生成的证据**，脚本不依赖 `.local` 中任何已有配置、工具、凭据或账号数据。可以用 `--output` 指定其他新目录。

## 4. 停止、失败与保留数据

按 **Ctrl+C**，或在另一终端创建停止文件。下面的路径应使用脚本开头打印的真实值：

```powershell
New-Item -ItemType File -Path '<本轮证据目录>\STOP'
```

脚本在**每一条 HDC 命令之前**检查停止信号，等待间隔也每 0.1 秒检查一次。发现停止信号会终止当前本机 HDC 等待，不再发送下一条设备命令，包括清理、Back、强停或恢复命令。已被设备接收的当前点击或输入可能已经发生，不能用 Ctrl+C 撤销。

- 退出码 `0`：本轮所有请求的单端步骤完成，包含保存、原文和出处回读。双端同步字段仍为 `false`。
- 退出码 `1`：前置条件、页面、命令或回读不符。查看 `result.json` 的阶段及 `commands.jsonl`，人工检查现场后换新测试库重跑。
- 退出码 `130`：收到停止文件或 Ctrl+C，已有进度和草稿保留。
- 参数无效由 argparse 返回 `2`；此时不发送设备命令。

脚本每次定位都重新获取布局，按真实 ID、裁切范围和启用状态操作。寻找屏外控件时，只在当前真实 Scroll 内进行有界滚动，每次滚动后重新定位；页首进度明确向上查找，屏外保存提示与正文先滚入视口再断言。无进展、找不到或发现重复 ID 都停止。它不在失败后尝试固定坐标补点。

输入失败时不要把未保存文字当成保存成功，滑条失败时也不会补造已完成进度。脚本不自动清理任何档案、笔记、进度、身份、原生 KV 或会话。删除已保存演示笔记只能由人工通过应用现有删除入口完成，正常保留墓碑；库残留可以保留作证据。

## 5. 证据与隐私

成功步骤按序生成原生 PNG 和对应的应用布局，例如空白感想、实际输入、本机保存、顶部最近记忆、正文与出处。`commands.jsonl` 按命令记录阶段、参数、耗时、退出码和原始 stdout/stderr；`result.json` 记录本轮阶段、结论、公开测试文字、图片 SHA-256 以及请求的目标。

脚本的默认成功截图不包含账号页、登录页、输入法或其他应用，实际输入后先关闭已识别的键盘再截图。全窗口布局仅在系统临时目录短暂读入，用于识别键盘、分享与遮挡；通过检查后，证据布局只保留云河纪应用树。检测到登录凭据或个人设置节点会阻止保存证据。脚本没有账号、密码或 token 参数，也不读取会话库或服务端日志。公开失败历史中的键盘现场是主线程另行采集并检查的空白感想画面，不公开完整系统 raw fixture。

为避免把旧个人文字拍入长卷，演示前必须没有亲笔记忆，保存后必须恰好一页，且顶部最近记忆的标题和全文与本轮一致。遇到分享面板的未知项目或可能的联系人推荐，脚本跳过面板截图，使用刚重新识别的真实分享面板执行 Back 取消，再以失败状态结束供人工核对。

临时布局与截图位于设备 `/data/local/tmp/yunheji-roaming-demo-<本轮编号>.json/.png`，正常接收后逐个删除。停止信号优先，因此中断后可能保留最后一个临时文件；`result.json` 的 `remoteTemporaryBase` 给出本轮确切前缀。人工清理时只处理该前缀的两个临时文件，不枚举或删除应用档案。本机临时布局由 Python 临时目录管理，不作为公开证据保存。

运行失败不会自动补拍“失败现场”，以免未知弹窗或账号内容落入截图。公开引用结果前仍应人工查看实际 PNG 与原始日志，确认文件来自对应本轮和目标包。定向 UI 脚本的完成状态不等同于 Hypium 的 `Pass / Failure / Error` 统计。

## 6. 人工接续到同账号的另一台设备

传入 `--tablet` 只说明准备了另一台设备。脚本不登录、不建立账号服务、不控制平板，也不制造同步动画或成功时间。完成单端演示后，人工接续现有原生入口：**个人页 → 账号与同步**，按真实页面状态登录或刷新；只有另一端读到实际记录才算账号延续。

需要区分当前记录归属：

1. 如果本轮通过“离线浏览本机档案”进入游客库，刚写的这一页留在游客库。现有产品不会在登录时自动把游客文字上传到账号；直接在另一端登录后找不到这页是预期行为，不能宣称游客页已经同步。
2. 要演示**同一条记录**的跨端延续，先由人工在两端以本轮独立 scope 打开应用，实际登录同一个演示账号，并在手机回到该账号的空白漫游工作区，再执行单端路径。脚本冷启动传入的同一个 scope 后，应用按真实身份恢复该工作区。不得输入或修改账号数据库来跳过登录，也不能把正式账号工作区冒充本轮独立 scope。
3. 若已完成游客演示，也可以人工登录后在账号工作区重新创作并确认保存一页，再演示这条新的账号记录；这与游客页是两个存储范围，应如实说明。
4. 确保两端应用实际配置并可访问同一个 HTTPS 账号服务。在手机“账号与同步”看真实待同步数量与状态，在平板登录同账号并刷新，随后返回“我的黄河长卷”，打开真实最近记录，逐字核对正文、文化摘录和出处。登录与账号状态画面含私人信息，应在脚本结束后人工操作并避免录入公开证据。
5. 演示离线修改时，先确认账号身份已恢复，再在手机离线状态修改并保存；网络恢复后等待真实交换，在平板打开同一条记录回读。记录本轮网络条件、两端包版本和实际结果，不能用安装实例 `deviceId` 充当账号身份。

HTTPS 同账号同步与鸿蒙可信设备传输是不同能力。系统可信设备数为零时，应展示实际“等待可信设备”或“尚无跨端确认”；不能用两台 HDC 在线、同一自建账号或本机 KV 写入代替原生传输证据。现有边界见 [账号恢复与原生同步说明](ACCOUNT_RESUME_AND_NATIVE_SYNC.md)，最新设备结论以 [TEST_REPORT.md](TEST_REPORT.md) 为准。
