## 2. 本阶段边界

- 保持 **HarmonyOS 7 / API 26、ArkUI 原生页面、现有 HDS 导航与 HTTPS 同账号同步**。不做 HarmonyOS 6 兼容，不改成网页，不重写渲染引擎。
- 页面沿用 Yi_Da 暖白与玫瑰设计语言；顶部与 Dock 继续使用现有官方原生材质，右下“我的”保持独立入口。本阶段不做一轮新的首页视觉翻新。
- “跨端”始终指同一个人的账号数据在两台设备间延续，不做多人协作。安装实例 `deviceId` 不等于账号身份；HTTPS 同步不称为鸿蒙分布式 KV。
- 只通过 HDC、Hypium、模拟器 CLI 或设备侧已核实接口直接操作模拟器；用户已授权安装和 UI 回归，**禁止控制电脑桌面**。用户停止设备操作时立即停止。
- 三处内容仍为“初稿待校审”，模型和 SVG 仍为原创学习示意；不冒充文物照片、测绘、实物扫描或考古复原，不增加没有依据的演化/传播结论。
- “泥火成器”保留庙底沟、大河村、杜岭二号方鼎、开封铁塔四节点。仅打开不算完成，75%显式探索或有效手账的点亮规则不变；不得为演示伪造全线完成。
- 保留旧笔记、revision 1 回放、删除墓碑和损坏读取保护。优先沿用 schema v1 和现有可选字段；确需调整格式时补兼容说明，不能自动补造旧观察记录。
- 验证只覆盖本阶段演示主线及具体修复；不主动扩展大字体、泛化安全、无关边界、全套离线冲突或生产治理。公网部署、华为账号、分布式 KV、备份恢复、新城市与大量内容均暂缓。
- 必要中文注释说明规则、原因和修改边界。可以沿用已获授权的必要测试适配，不能删除业务断言把失败改成通过；不改用户签名、证书或无关配置。

## 4. T11：双端真实操作与核对

### 4.1 准备两台设备与同一份构建

1. 用 Emulator CLI 和 `hdc list targets` 核对实例与实际 target，记录A/B映射、系统/API、分辨率和密度。上一轮最后在线的是 `YunhejiSyncB`、`127.0.0.1:5555`；历史上该实例用过5557，**端口不是固定身份**。
2. 如果只有一台在线，使用CLI启动另一台既有API26实例，保留数据；只有不存在合适实例时才按已有环境创建第二台。不要克隆正式账号档案或重置既有模拟器。
3. 使用既有本机账号服务与两条HDC反向端口。启动脚本会保留占用端口的进程，重复执行不保证重新加载领域代码；先确认监听者确属本项目。若运行进程加载的是旧版手账解析规则，只重启本项目对应服务，保留原数据库、证书和端口。
4. 使用 `prepare-account-test.mjs` 生成一次本轮随机账号fixture，两端使用同一份fixture，不在A/B之间再次生成。凭证只留在已忽略的测试资源和 `.local/`，不写入文档、截图或主包。
5. 先生成/确认服务配置和测试资源，再构建两包并记录哈希，然后在两端安装同一版本。运行前确认包晚于相应源码与资源；原始阶段清单绑定的是实际安装包。
6. 两端均从真实登录页进入本轮独立账号。可以在计时展示前完成登录和设备解锁；不能跳过T11对真实登录路径的核对。

### 4.2 A端发布阶段

优先选择已经在首页路径通过的 **庙底沟 `smx-miaodigou`**，以 **西部陶窑 `kilns`** 为本轮双端样板。

1. A端从首页“泥火成器”进入庙底沟；独立空账号下仅打开仍为0/4。
2. 切换具体观察部位，核对模型高亮、部位名和事实正文同步变化。选择西部陶窑，再主动右转或拖动到区别于推荐镜头的角度，避免默认镜头掩盖恢复失败。
3. 通过“留住此刻”进入原生编辑器，保留事实摘录，选择受支持的印章与纸色，真实输入本轮可识别的个人文字和标签后保存。
4. 以正式保存结果为准。移除该测试库的缓存后回读磁盘，记录同一note的ID、来源版本与完整手账字段；测试不得先注入预制note或改写快照冒充保存。
5. 返回首页，确认最近记忆、真实预览、1/4及下一处大河村。采集保存前取景和A端卡片，保留同次dumpLayout与连续绘制日志。

正文示例可用“在陶窑与居住遗存之间，记下我对庙底沟西部空间关系的观察。”；它是个人观察文字，不新增考古结论。run标记可放在合成测试标签中，只用于区分本轮记录。

### 4.3 B端接收阶段

1. B端登录同一账号，确认其独立库在接收前没有本轮note ID。账号身份相同，两端安装实例身份保持各自原值。
2. A端保存后，B端在前台执行现有交换并等待实际接收。记录保存、交换成功与B端显示的实测时间，不伪造“秒传”或固定成功时间。
3. B端从独立Preferences回读新note，与A端已保存记录核对下表；不能把A端文件复制到B端、手工灌库或直接写测试数据当成同步。
4. B端首页显示最近记忆与真实1/4；进入“记忆”确认同一记录、文字、标签、摘录与装饰。至少一处卡片必须实际显示重建模型。
5. 点击B端卡片画面进入正式回放，确认对应庙底沟、`kilns`、保存的相机和原画幅。等待真实绘制回调后检查模型；“已恢复”文字或参数解析通过都不能单独作为完成依据。

| 信息组 | 必核字段/行为 |
|---|---|
| 记录身份 | `id`、`kind`、`siteId`、`updatedAt`、记录的`deviceId`、`deleted`；源记录身份不得被B端改成新笔记，B端快照自身的安装ID仍独立 |
| 用户内容 | `body`、`tags`、`quotedPoemOrFact` |
| 装饰 | `stampType`、`paperTheme` |
| 观察选择 | `snapshot3DPose.version / sceneType / hotspotId / sectionId / label` |
| 相机 | `yaw / pitch / zoom`，核对保存值与B端实际绘制值 |
| 场景资源 | `proceduralPreset / sceneRevision / rendererProfile`，本轮样板为`miaodigou_pottery / 2 / native-raster-v1` |
| 原取景 | `viewFrame.width / height / textDensity / dark`，B端预览按保存画幅contain，不用当前卡片尺寸重算取景 |

### 4.4 跨端画面验收

- 同时保留A端保存前完整Canvas、B端卡片预览和B端正式回放原图，以及同次布局与绘制参数。检查模型确实可见、没有被截断，选中部位和说明一致。
- 使用既有同场景参数重建；跨端预览不得依赖A端本地图片路径，不增加截图上传服务。
- 同分辨率、密度和绘制版本时，按Canvas边界核对A保存/B回放；存在尺寸差异时，按保存的虚拟画幅去除contain留白并等比对照，记录实际差异与方法。不得把上一轮本机“零差异”直接套用为跨端结果，也不要强求不同物理尺寸的整屏PNG相同。
- 若B端缺失对应场景或不支持修订，明确显示原因并保留笔记；这属于本轮阻塞，不能悄悄用默认模型宣布T11完成。
- T11首先交付这一条完整样板，不要求重跑20条档案、三处对象所有组合或旧账号八阶段全套。只有选定最终演示对象改变或发现对象特有问题时，增加对应的定向验证。

## 5. T12：只修影响本条主线的问题

重点排查：账号服务未加载新解析规则导致字段丢失；同步响应后未正确落盘；合并时元数据被省略；首页最近卡或路线未刷新；跳转丢失pose；B端场景版本失配；预览空白；相机恢复后被默认镜头或自动转动覆盖。

每个问题记录“实际触发 → 原因 → 最小修改 → 对应复验”，不借此重构整个账号/存储系统。当前会话保留在进程内，冷启动需重新登录：默认通过演示前登录解决；只有实际排练证明该限制阻断本条主线时，才纳入必要修复。不得提前开展完整会话持久化、离线冷启动、冲突治理或安全测试项目。

若修改账号解析、复制或合并规则，保留旧记录、可选字段和墓碑语义，并运行相关的现有测试；`domain/*.ts`继续保持无`@kit.*`和平台UI/存储依赖。复杂规则补必要中文注释。

## 8. T13：三分钟脚本与真实备用录像

### 8.1 计时前准备

### 8.2 排练草案

| 时间预算 | 实际操作 | 评委需要看见的结果 |
|---|---|---|
| 0—15秒 | A端首页点击泥火成器进入庙底沟 | 主题直达，明确核心问题，路线仍为真实进度 |
| 15—40秒 | 选择居住/西部陶窑，转动观察 | 部位、画面与事实同步；说出“西部陶窑与居住遗存共存”这一具体发现 |
