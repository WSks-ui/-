## 2. 当前可以操作的完整路径

四个原生页签为 **漫游 / 文化库 / 记忆 / 我的**。首次进入新漫游首页，未登录即可剪纸；不需要请求模型或联网才能完成五城空间目标。

1. **漫游：** 选一城，读一句空间目标，进入整屏纸景。玩家用真实指尖笔迹开剪口，尝试平纸、对折、四折和展开；可以换纸色、透光、撤回最多四次动作或确认换新纸。独立移光模式下，真实 mask 的投影跟随手指改变，本地光位不写进度；移光后可切回继续剪。完成状态由实际纸面关系产生，纯开灯、换色或进入页面不会通关。
2. **文化资料：** 查看这座城的文化说明、各条短引/资料摘要、年代和原出处。可在原生文本中选摘材料，再点击或通过 UDMF 拖放加入草稿；纸景 M12/T12 已验证完整 292 字摘录和三条来源在明确保存后重读保持。
3. **收进记忆：** 达成城市目标不会自动新建 note；玩家明确确认保存当前作品，可以手写感想，也可以只保存作品。没有自动填入个人感受，不把后续剪纸覆盖到这页冻结作品上。
4. **记忆：** 作品优先呈现，保存时的纸面只读预览、文字、摘录与来源可重读；不同记录按真实 note ID 打开。手账的标签、关键词、最近/最早与 AI 筛选收进原生面板，收藏保留独立分区与分类。
5. **文化库和我的：** 文化库首屏给真实照片、正文摘要和阅读入口；筛选进入原生面板。我的页简洁呈现真实数量，账号 HTTPS、本机保存与鸿蒙可信通道分开显示，账号、存储与偏好仍由既有原生功能页处理。

默认主线不再进入旧开封拖桥/探方。旧篇章作为导读从文化库保留，旧个人长卷从记忆/我的进入；旧页面与旧数据不是被新主线覆盖或伪装为新纸景。

## 5. 数据格式与合并

档案外层继续 `schemaVersion=1`。本轮不覆盖或重命名旧库，不改旧记录 stable ID，没有必须先清库的迁移步骤。

| 数据 | 身份与内容 | 合并/删除规则 |
|---|---|---|
| 纸景当前进度 | `kind=progress`，`id=progress:paper-journey:v1:<cityId>`，`siteId=<cityId>`；body 是 `PaperWorkV1`。 | `mergeRecords` 实际调用 `GameProgressMerge`，先严格核对 ID、城市和正文；当前编辑整条 LWW，不按位叠加两端 mask。完成时间/完成 mask/纸色作为实际完成快照独立保留；墓碑仍按原版本比较。 |
| 纸景最近位置 | `progress:paper-position:v1`，正文与 siteId 均为纸景城市 ID。 | 普通版本信封，不能当作作品完成或真实到访。 |
| 确认保存的作品 | 普通 note，真实 `note:<deviceId>:<logicalTime>`，siteId 指向对应已有文化档案；可选 `paperContext`。 | 正文、标签、时间、来源和作品为同一条 note 的冻结上下文。整条比较，不把两篇 note 的来源或作品拼接。 |
| 旧漫游/开封城/探方 | 各自旧 `progress:roam:*`、`progress:kaifeng-city:*`、`progress:kaifeng-dig:*`。 | 保留旧身份；城的完成与材料并集、探方局号/历史最佳的语义适配已接通用合并，不会把旧记录解析成新纸景。 |

纸面是展开后的 40 列 × 48 行，mask 为 480 个十六进制字符；保留最多四步历史、平纸/对折/四折、纸色、透光和时间。剪口由真实动作产生，换新纸保留已有完成快照，不影响已经保存的 note。透光开关属于作品状态，独立移光模式的手指光位只作本地观察，不写进度或更新时间。codec 验证外框、历史与完成快照，损坏正文不补成空白纸。

已有 active 记录出现错误 kind、siteId、正文或城市时，`paperWorkIsUnreadable(records, cityId)` 明确识别不可读作品。Index 在队列真正提交前再次检查，提示错误并保留原 body 与快照，连最近位置也不写；页面禁用剪纸并展示不可读说明。此保护区分“原本没有作品”和“作品存在但损坏”，不能用新空白 mask 覆盖后者。

`paperContext` 包含 `version/cityId/title/culture/work/sources`，可选 `excerpt`；来源冻结 `id/title/url/quote/accessedAt/era`。`copySnapshot`、解析校验与版本比较均保留这些字段。创建时作品 history 清空，仅冻结当前实际作品和当时完成快照；之后在另一端续剪不会改写它。缺省 `paperContext` 的旧笔记不补值。

保存路径是“页面动作 → 页面队列 → Index 读取最新共享快照和逻辑时间 → Repository flush → 发布状态 → 同步”。连续动作不因写锁直接丢弃；保存失败有单独未保存状态。成功排空队列后重新看最新 records，避免 pending 期间收到的更新一直不显示。同内容本机回包仅确认时间，不误提示另一端更新。M14 已包含上述修复，本轮最终本地结果为 241/241；T14 保存/撤销/冷重开用例与 T15 入口单例分别通过，原生设备证据按下表的实际阶段保留。
