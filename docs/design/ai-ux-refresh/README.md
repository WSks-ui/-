# 2026-10-19 AI 界面检查与统一改版

范围：云河纪中所有与 AI 观察相关的窗口与入口。目标不是增加功能，而是把已经存在的 AI 能力做成一致、可读、可现场演示的界面。

## 1. 检查范围

| 界面 | 位置 | 检查内容 |
|---|---|---|
| 首页 AI 主卡 | `Index.homeAiQuestionCard` | 对象选择、问题层级、CTA、1.5 倍字体 |
| 档案页 AI 入口 | `Index.archiveAiRow` / `library-ai-card` | 双对象入口、缩略图、筛选一致性 |
| 文化档案详情 | `SiteDetail` + `AiObservationPanel` | 面板位置、展开/收起、对象上下文、回答、动作、依据 |
| AI 等待 / 错误 / 游客态 | `AiObservationPanel` | 加载反馈、失败恢复、登录提示 |
| AI 手账草稿 | `AiObservationPanel.draftBlock` | 草稿层级、长文、标签、参考事实、采纳/放弃 |
| 记忆列表 | `MemoryPostcardItem` | AI 辅助标签、问 AI 按钮、与其它标签的区分 |
| 手账全文 | `MemoryDetailPage` | AI 记录块、保存时依据、带手账问 AI |
| 我的 / 资料说明 | `ProfilePage` | AI 统计、入口命名、AI 范围说明 |

检查方法：逐文件走查 + 现有设备截图（`docs/design/ai-observation`、`docs/design/page-hierarchy`）+ 真实模型小样 + 构建与本地测试。设备截图来自改版前，本轮改版的设备复验见第 6 节。以下 19 条均已在代码中处理；设备功能复核已完成 4/4，1.5 倍 / 深色专项见第 6 节。

## 2. 发现的问题

### 信息层级与流程

1. **AI 面板埋在长正文之后。** 详情首屏是模型与资料，面板在数段正文下方；演示时需要先滚动很久。
2. **回答头部信息打架。** 状态胶囊、“当前资料不足”提示、“当前观察 · 部位”三者同排，主次不清。
3. **依据出现两次。** 模型动作“查看依据”与固定按钮“查看本次依据 · N 条”并存，点哪一个都能展开，语义重复。
4. **动作主次不分。** 聚焦与依据都是等宽白底按钮；三条动作把回答推得很长，宽屏还浪费横向空间。
5. **草稿把关键操作推到屏幕外。** 长草稿全文 + 标签 + 事实 ID 后才出现“采纳 / 放弃”；参考事实直接显示 `duling-eight` 这类内部 ID。
6. **等待态高度跳变。** 只有一行 spinner，回答到达时面板突然长高；没有稳定的占位。
7. **错误态缺少退路。** 只有错误文案和“重试”，没有“继续手动观察”，游客/服务未配置时也没有明确登录路径。
8. **游客态只是说明文字。** 用户不知道下一步去哪；面板标题之外没有可点的引导。

### 一致性与视觉

9. **入口命名不统一。** “AI 观察导览”“AI 导览”“和 AI 一起看方鼎”“与 AI 观察方鼎”“问 AI”“带着这页手账问 AI”混用。
10. **AI 语义色漂移。** 入口用青色，面板图标/状态用玫瑰色，记忆标签也用玫瑰色；同一能力出现三种视觉身份。
11. **圆角与高度随手写。** 7/8/9/10/11/12/13/14/18 混用；按钮高度 30/32/34/36/38/40/42/44 混用。
12. **AI 筛选与页内控件不一致。** 记忆与档案页的“AI 辅助 / 可 AI 观察”是裸 Checkbox 行，旁边却是 chip / 分段按钮。
13. **首页与档案仍只写方鼎。** 双连壶已可问，但入口文案没有体现，用户不知道还有第二件。
14. **标题栏只有小按钮可点。** 展开/收起依赖右上角 34 高按钮，点击区域小。

### 响应式与可用性

15. **固定高度在大字体下有裁切风险。** 36/38/40 高的按钮配 14—16fp 文案，1.5 倍字体时余量不足。
16. **首页两个对象 chip 在 1.5 倍字体下可能横向溢出。**
17. **动作竖排全宽，宽屏不利用横向空间。**
18. **关键控件缺少无障碍文本。** 起始问题、聚焦动作、依据开关只有视觉文本，读屏缺少动作语义。
19. **输入校验提示不可见。** 空问题或超长问题只写入 `errorText`，但错误块仅在 `phase === 'error'` 时渲染，点击“提问”看起来没有反应。

## 3. 统一方案

### 3.1 语义与命名

- 能力统一叫 **AI 观察**；入口统一为 **和 AI 一起观察**；手账动作统一为 **问 AI**；保存后的记录统一标 **AI 辅助**。
- **青色 = AI / 资料 / 依据**：入口卡、面板图标、对象上下文、状态胶囊、依据块、草稿标签、AI 辅助标签。
- **玫瑰 = 用户确认的主操作**：提问、采纳并编辑、带手账问 AI（已有 AI 依据时）。
- **黄色 = 资料不足**；灰色 = 元数据与次要说明。避免把“AI 参考”做成和“印章 / 纸色”同一种装饰色。

### 3.2 尺寸令牌（AI 区域）

| 项目 | 取值 |
|---|---|
| 面板圆角 / 内层卡片 | 18 / 14 |
| 列表行 / 控件 | 12 / 11 |
| 小标签 | 8 |
| 面板内边距 / 组间距 / 行间距 | 16 / 12 / 8 |
| 主按钮 / 次按钮 / 控件最小高度 | 44 / 42 / 40 |
| 起始问题行最小高度 | 44 |
| 动作 chip 最小高度 | 38 |
| 文本展开 / 收起 | 30 |

按钮从固定 `height` 改为 `constraintSize({ minHeight })`，让 1.5 倍字体自然撑开；长文本统一 `maxLines + Ellipsis`。

### 3.3 面板结构

```text
[图标] AI 观察                     ⌄   ← 整行可点
在线模型 · 已核事实

大河村彩陶双连壶 · 腹部通口           ← 单一上下文条（对象 + 部位）

[回答卡]
  状态胶囊                     依据 · 2 条
  回答（默认 3 行，可展开）
  [看腹部通口] [看两只壶口]        ← 动作 chip，自动换行
  [原始资料 / 馆方来源 / 事实卡]     ← 依据开关唯一入口

[问这件器物] 0/200
[输入框]
[提问]

[把这次发现留下] AI 整理
[个人观察输入]
[整理为手账草稿]
  └ AI 建议草稿（默认 4 行，可展开）
     #标签  #标签
     依据：事实标题
     [采纳并编辑] [放弃]

AI 仅使用本件 3 条已核事实与 3 个观察部位；资料不足会明确说明。
```

- 回答之后紧跟追问输入，草稿作为第二步放在其后，避免“继续问”被长草稿推走。
- 依据只保留一个开关；模型返回的 `show_evidence` 合并到该开关，不再渲染第二颗按钮。
- 动作只渲染 `focus_hotspot`，按内容宽度换行；`show_evidence` 不再单独成按钮。

### 3.4 状态设计

| 状态 | 处理 |
|---|---|
| 游客 | 标题 + 说明 + **登录入口：我的 → 账号与同步**；强调离线仍可手动观察 |
| 服务未配置 | 说明在线 AI 暂不可用，手动能力保留 |
| 等待 | spinner + 已等待秒数 + 三条静态骨架，稳定高度；可停止 |
| 错误 | 标题“这次没有生成回答” + 真实原因 + 重试 / 手动观察 |
| 资料不足 | 黄色状态胶囊，文案明确“当前资料不足”，不推测 |
| 草稿 | 默认 4 行预览，标签 chip，事实显示中文标题而不是内部 ID |
| 输入校验 | 在输入框下方显示红色行内提示，随输入清除；不占用网络错误块 |

### 3.5 入口改造

- **首页**：单张主卡保留，增加“杜岭二号方鼎 / 大河村双连壶”两个 chip；问题与 CTA 随对象切换，显式“进入…”按钮负责导航。
- **档案页**：单个入口改为“和 AI 一起观察”双行卡，各行有缩略图、对象名、引导问题；`library-ai-open` 仍指方鼎，新增 `library-ai-open-dahecun`。
- **我的**：菜单改为“AI 观察 / 方鼎与双连壶”；统计卡仍显示真实 AI 辅助手账数。
- **记忆**：AI 辅助标签改青色；问 AI 按钮与相邻按钮统一圆角与高度；手账全文的 AI 依据收进独立浅色块。

## 5. 响应式与无障碍

- 动作 chip、首页对象 chip 使用 `Flex` 自动换行，不写死百分比宽度。
- 关键按钮使用 `minHeight`，长文案允许换行；1.5 倍字体下不依赖固定高度。
- 标题、对象名、问题、动作标签均设置 `maxLines + Ellipsis`，避免横向撑破。
- 面板标题、起始问题、聚焦动作、依据开关、草稿采纳、输入框和发送按钮均补充 `accessibilityText`。
- 深色模式沿用 `home_mint #293B34` / `home_mint_ink #B3D9C8`，与浅色语义一致；未新增硬编码颜色。

### 6.1 截图复核发现并修复

1. 方鼎对象说明被限制为 1 行，截图出现“比例与乳钉点数已简…”截断；改为 3 行，复跑后完整显示。
2. 聚焦后视口状态与 AI 返回条都写“已聚焦 · 四个折角”；AI 条改为“AI 已定位 · 四个折角”，避免重复。
3. 起始问题改为“序号 + 问题 + 箭头”复合按钮后，`Button.text` 为空，旧用例读到空字符串；给问题文本加 `ai-starter-text-*` id，用例改读文本节点。
4. 上下文条“正在看 · 对象 · 部位”在 1.5 倍字体下会截掉部位；缩短为“对象 · 部位”。

### 6.2 未通过项与归因

`ArchiveAppearanceTest`（浅/深色与 1.5 倍字体）尝试 6 次仍未通过，失败点均为用例自身的旧导航假设，不是 AI 功能回归：

- 记忆页默认已改为“手账”，用例直接等待“收藏”分区的 `collection-filter`；
- 同步值位于“账号与同步”分区，用例未展开该分区就 `inScroll`；
- 1.5 倍字体重启后应用回到首页，用例仍假设停留在记忆页；
- 继续补上 `tab-1` 后，重启后的 `archive-scroll` 仍不可用；现场应用已退回桌面，设备 `faultlogger` 没有 2026-10-20 的新 crash / freeze 记录。

因此 **1.5 倍字体与深色模式下的 AI 面板专项截图仍未取得**；代码层已使用 `minHeight`、`Flex` 换行与单行截断降低溢出风险，但不能据此宣称视觉已验收。双连壶独立保存与跨端重访（PX05）同样未跑。

## 7. 未改变的行为

- 不改 AI 契约、事实白名单、热点、资料修订、模型配置或错误码。
- 不自动聚焦、不自动保存、不伪造同步或 AI 成功状态。
- 不改既有测试 ID 的业务含义；`ai-action-*` 的 id 从序号改为热点 id，现有用例通过文本定位，不依赖该 id。
- 不把 AI 能力扩展到庙底沟或其余 17 条档案。
