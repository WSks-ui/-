# 云河纪：软件功能规划背景

## 1. 产品定位

云河纪是一款以河南段黄河文化为主题的鸿蒙原生应用，面向个人的文化探索、出游、研学与记忆留存。

用户应当能够发现感兴趣的文化内容、理解其中的故事、获得互动体验，并留下属于自己的文化记忆。收藏、笔记和图谱服务于这些体验，不是软件的全部。

“跨端延续”是同一账号在多台设备上同步个人信息，不是办公交接，也不要求同时整理专题。

本次规划的目标是：**在现有软件上形成更丰富、更有吸引力、有明确创新的产品体验，而不是继续完善资料管理工具。**

## 2. 当前已有的功能

| 模块 | 现有能力 |
|---|---|
| 文化浏览 | 五城入口，按城市、年代、类型筛选，关键词搜索，文化详情分层阅读 |
| 收藏与记录 | 收藏分类、文字笔记、时间戳、自定义笔记标签、浏览记录 |
| 关联探索 | 根据收藏与浏览推荐相关内容；可点击的“文明连线”图谱、双遗址对照、个人专题 |
| 账号与同步 | 独立账号注册登录；两台设备间真实同步收藏、笔记、标签、浏览记录及修改、删除 |
| 离线使用 | 现有正文和插画预置本地，收藏笔记本地保存，已登录状态下离线修改后重连同步 |
| 原生体验 | ArkTS / ArkUI，HarmonyOS 7 / API 26；HDS 顶部材质、悬浮 Dock、深色模式与字体适配 |

目前的内容只有五条：仰韶村遗址、二里头遗址、郑州商城遗址、开封铁塔、戚城遗址。内容仍是待校审初稿，图片主要是重复使用的主题插画；诗词、文旅信息和文物独立条目尚不充分。

已有同步使用自建账号与 HTTPS 服务，尚未接入华为账号和鸿蒙分布式数据库。阅读状态目前只是“打开过”，没有完整阅读进度；一键备份恢复尚未实现。

登录和个人页正在调整，“教育计划”目前只有界面占位，不能作为已有业务能力。现有视觉沿用暖白、玫瑰和粉彩设计，可以在此基础上提升。

## 3. 当前产品的主要问题

1. **体验集中在看资料和做记录。** 虽然有多个模块，主要操作仍是浏览、收藏、写笔记，再以标签或连线重新展示这些资料。
2. **文化内容没有充分变成体验。** 黄河的空间关系、文明的时间变化、遗址背后的故事，还没有成为用户能主动参与的探索过程。
3. **内容太少，限制所有关联功能。** 五条初稿导致搜索、推荐、对照和图谱反复出现相同对象，也缺少真实图片与更丰富的内容层次。
4. **个人记忆的表达单一。** 目前主要是收藏列表与文字笔记，尚未形成鲜明的个人文化体验。
5. **缺少持续使用的理由。** 用户首次浏览后，为什么还会回来、接下来能发现什么，目前没有清晰的产品设计。
6. **创新还没有形成整体。** 图谱提供了一个可见亮点，但不足以独立支撑整个应用的丰富度；需要让内容、交互、个人记忆和鸿蒙能力相互配合。

## 4. 与软件开发有关的赛题范围

选择赛题一“黄河记忆·黄河文化分布式数字档案”。核心目标是整合河南段黄河沿线文化遗产，提供沉浸式文化探索，形成个人文化记忆库。

赛题给出的主要功能范围：

- **内容组织与检索：** 年代覆盖仰韶、龙山、夏商、周、汉唐、宋；城市包括三门峡、洛阳、郑州、开封、濮阳；类型涉及都城遗址、墓葬群、窑址、古建筑等。
- **多层文化内容：** 图文介绍、考古发现、历史事件、相关诗词、现代文旅信息，而不只是遗址简介。
- **个人收藏与笔记：** 支持遗址和文物条目、个人分类、自定义笔记与时间戳。
- **同账号多设备与离线：** 个人数据自动同步、离线编辑后恢复同步、冲突处理和真实同步状态。原文涉及同一华为账号与鸿蒙分布式服务，现有自建账号同步不等同于已实现这些技术。
- **关联推荐：** 根据浏览与收藏发现相关遗址、文物和文化脉络。

原文另列主题知识网络、备份恢复、多端笔记编辑等创新拓展，可以参考，但不必全部实现，也不应因此把软件做成办公产品。

这些是产品范围，不是限制创新只能在上述按钮和列表内展开。新功能需要紧扣黄河文化、个人探索与记忆，并能在原生界面中直接体验；鸿蒙特性应有实际用途，文化事实与素材需要可靠来源。

## 5. 希望下一步规划深入回答的问题

1. **完整产品结构是什么？** 明确用户进入应用后有哪些主要去向，各模块如何连接，哪些现有功能保留、调整或弱化。不能只在首页继续堆入口。
2. **如何真正丰富探索体验？** 提出具体的功能组合，说明用户能做什么、过程如何变化、能获得什么结果，而不只是多几种资料展示方式。
3. **文化内容如何组织得更有吸引力？** 说明城市、年代、遗址、文物、事件和诗词之间怎样建立有意义的联系，以及需要补充哪些内容与素材。
4. **个人记忆可以如何发展？** 让用户留下自己的体验与理解，而不是要求用户承担研究整理工作；同时说明这些新数据如何随账号跨设备使用。
5. **鸿蒙原生能力如何参与体验？** 结合设备形态、原生组件、动效与沉浸光感设计实际交互，不把技术名词或装饰效果本身当作功能创新。
6. **怎样拆成可开发的迭代？** 每项功能明确页面、操作路径、数据模型、素材需求、平台或服务依赖，以及与现有模块的关系，给出优先级和最小完整版本。

期望输出的是一份能指导后续开发的产品方案：**整体结构 + 功能设计 + 关键页面与交互 + 内容和数据需求 + 实现依赖 + 迭代顺序**。重点放在软件本身，不包含赛事行政事项或工程过程汇报。
