# 云河纪独立账号与双端同步

日期：2026-10-14。用户明确允许在没有华为开发者应用记录的情况下，先用独立登录方案跑通，并创建第二台鸿蒙模拟器验证。

## 当前实现

**2026-10-21 更新：** 已实现原账号工作区的离线冷启动与系统 ASSET 会话恢复；新增原生分布式 KV 本机版本库、权限与系统可信设备查询。当前模拟器可信列表为 0，原生跨端没有完成，HTTPS 仍是已走通的双端通道。用户选择模拟器和开发机服务，没有腾讯云域名；客户端已支持可选公网 HTTPS 配置，尚未部署。完整边界及复现见[账号恢复与原生通道](ACCOUNT_RESUME_AND_NATIVE_SYNC.md)。下文标注 10-14 至 10-19 的路径是历史实现说明，过期处以本段与新说明为准。

2026-10-16 更新：应用启动先显示独立登录 / 注册页，账号状态与退出入口移至右下角 Dock 外的“我的”；“档案”保留本地资源状态。大学 / 学号仅作本次会话的教育计划占位，不加入认证或同步，详见 [页面说明](LOGIN_PROFILE.md)。收藏、分类、笔记、标签和浏览记录仍经原生 `NetworkKit.http` 通过 HTTPS 与账号服务交换。服务端使用 Node.js 和 SQLite，默认只监听回环地址；校赛演示也可显式绑定同网段私有 IPv4（见下文“局域网演示模式”）。两台模拟器通过各自 HDC 反向端口连接同一服务。

HTTPS 是自建账号服务的网络同步。华为账号授权尚未接入；原生分布式 KV 已有本机版本库与独立状态，但可信组网和跨端传输未验收，不能将 HTTPS 路径改称为相应能力。当前演示不依赖多人同时编辑，个人图谱由已同步的用户记录派生。

- 注册、登录、退出均访问真实服务。密码使用随机 salt 与 scrypt，服务端只保留会话 token 的 SHA-256；请求与日志不输出密码、token 或笔记正文。
- 服务端凭已认证会话选择账号，客户端不能提交账号 ID 来访问其他账号。
- 首次登录打开独立 `yunheji_account_v1_<账号ID>` Preferences。本机未登录档案 `yunheji_archive_v1` 保持原位置，未自动上传或合入账号。退出登录回到独立登录页，点击明确的离线浏览可访问原档案；再登录同一账号仍可读取其本机快照。
- 当前快照仍为 schema v1，记录字段和墓碑保持原值。没有格式迁移、清空正式档案或修改安装实例 ID。新建账号的档案从空库开始，后续连接后合并服务器记录。
- 保存操作先在本机确认，再触发交换；前台每 5 秒拉取 / 合并一次，在途请求不堆积，后台停止定时请求。请求期间的本机修改与当前快照合并，避免旧响应覆盖新编辑。
- 删除使用墓碑。服务端在 SQLite 事务内合并版本，保留落败内容的冲突版本；冲突历史的用户查看 / 恢复页面尚未实现。
- 同步成功时间仅在真实响应校验通过、远端变更本机落盘完成后更新。连接失败保留本机内容与上次时间，显示重试状态，不生成新的成功时间。
- “其他在线设备”来自同账号最近 45 秒执行过交换的不同安装实例，是服务端活动统计。它不表示设备已通过鸿蒙可信设备发现或认证。

账号工作区身份单独保存在本机 Preferences，网络会话只进入系统 ASSET。退出进程后先恢复原账号离线档案；会话有效时可继续联网交换，过期或 ASSET 不可用时要求重新登录后再同步/使用 AI，本机档案仍可读改。主动退出会忘记身份与会话，账号档案保留原库。阅读状态包括 `opened` 浏览记录及既有探索进度；材质 / 减少动态偏好留在设备本地。

2026-10-18 新增 AI 路由：已认证账号可通过 `POST /ai/observe` 请求方鼎 AI 观察导览。该路由在现有 `/sync` 排他判断之前分派，不占用同步数据库事务；请求仍使用账号服务同一 TLS 与 Bearer 会话，并按账号做每分钟 20 次限流。模型密钥只读服务端环境或被忽略的 `.local/ai-observation/config.json`，客户端不接触密钥、供应商地址或原始响应。未配置时返回 `503 AI_NOT_CONFIGURED`，不退回示例回答。实现、错误码和配置见[AI 观察说明](AI_OBSERVATION.md)。

## 本机启动

需要现有 DevEco Node.js 24、HDC、两台已启动 / 解锁的 API 26 模拟器和本机 OpenSSL。只操作模拟器命令行，不需要控制电脑桌面。

```powershell
.\tools\start-account-server.ps1 -TargetIds @('127.0.0.1:5555','127.0.0.1:5557')
.\tools\build.ps1
.\tools\build.ps1 -Target ohosTest
```

脚本首次生成本任务专用的短期 TLS 证书，私钥、账号数据库和服务 PID 位于被忽略的 `.local/account-sync/`。主客户端资源 `account-sync-dev.json` 只含本机 HTTPS 地址与公开证书，同样已被忽略；不包含服务器私钥。客户端使用 `caData` 验证证书与主机名，不关闭 TLS 校验。当前客户端只在 debug 运行时启用这个本机配置，release 的正式地址 / 证书与部署尚未交付。

AI 观察还需要本机 `.local/ai-observation/config.json`（含 DeepSeek 密钥、Base URL、模型和超时），该文件同样被忽略。缺少该文件或密钥时账号服务仍可启动，`/ai/observe` 返回未配置状态，账号和同步不受影响。不要在命令行、日志、截图或公开文档中粘贴密钥。

服务以隐藏后台进程运行，HTTP `/health` 只返回服务标识与版本。重复运行启动脚本保留既有端口；若请求的绑定地址与当前监听地址不一致，脚本会直接报错而不是静默沿用旧进程。发生冲突时应先核对监听进程，不结束其他应用。用户自己的签名文件 / 本机证书没有被替换。

### 局域网演示模式（2026-10-19）

校赛演示允许把账号与 AI 服务放在同网段的开发机上，模拟器直接经网络访问；仍不涉及公网部署，对外材料继续按“腾讯云过渡、鸿蒙账号为下一阶段”的既有口径表述。

```powershell
# 服务跑在本机另一块网卡 / 同网段电脑时，传入那台机器的私有 IPv4
.\tools\start-account-server.ps1 -HostAddress 192.168.1.20 -TargetIds @('127.0.0.1:5555')
```

- 端点白名单在领域层 `validateServiceEndpoint` 统一维护：只接受 `https://`、`localhost`、`127.0.0.0/8`、`10/8`、`172.16/12`、`192.168/16`，且只在 debug 包生效；release 与公网地址一律拒绝。
- 切换 `HostAddress` 会重新生成服务证书并把旧证书备份为 `.local/account-sync/server.pem.<时间戳>.bak`，同时改写 `account-sync-dev.json`。该文件会在构建时打进 HAP，**必须重新构建并安装**，否则设备仍连旧地址（`demo-check.ps1` 会核对包内副本）。
- 局域网模式不需要 HDC 反向端口；回环模式仍由启动脚本为每个 `TargetId` 建立 `rport`。
- 演示前运行 `.\tools\demo-check.ps1 -RequireDevices 2`，检查主包、包内端点、服务健康、在线模拟器、反向端口与 AI 配置。自检探针会临时跳过证书校验，仅用于确认端口可达；应用本身仍以包内 CA 校验证书和主机名。

第二台实例名为 `YunhejiSyncB`，与第一台使用相同 HarmonyOS 7.0.0.107 / API 26 手机镜像。最初 2GB 配置曾报告可用内存低，已保留配置后调整到 4GB 并采用保留数据的 coldboot。首次输入还有系统输入法设置，测试实例使用基本输入模式；没有同意全量输入法功能。

## 双端验证

```powershell
.\tools\test.ps1
& '<DevEco目录>\tools\node\node.exe' --experimental-strip-types --test server/account-service.test.mjs
.\tools\account-test.ps1 -DeviceA 127.0.0.1:5555 -DeviceB 127.0.0.1:5557
```

`account-test.ps1` 每次生成随机独立账号并构建测试包，按顺序运行以下真实路径，最后恢复两台设备的熄屏设置：

1. 空白账号入口、深色和 1.5 倍字体，截图不含账号 / 密码。
2. A 端经 UI 注册，先核对游客隔离，再收藏并保存中文笔记 / 标签；退出回读游客库。
3. B 端同账号登录，回读 A 保存的收藏、笔记、浏览记录，进入原生编辑器修改。
4. A 端收到 B 修改，第二账号注册后确认服务器与本机档案隔离。
5. B 端登录后停止本任务账号服务，经 UI 离线修改并回读本机磁盘，再恢复同一服务数据库与证书。
6. B 端重连上传待同步的离线记录。
7. A 端收到离线修改，经原生删除确认生成墓碑。
8. B 端收到墓碑，不复活旧记录。

最后两项清理用例只删除本轮的 `yunheji_test_ui_*` 独立 Preferences，不枚举正式库。服务数据库中的合成测试账号用于复查；其随机凭证只在被忽略的测试资源 / 本机文件，不进入主包或报告。测试截图只保留空白登录页、收藏列表与合成笔记详情。

不同设备上的用例有前后依赖，不能直接运行整个 `AccountSyncTest` suite 冒充双端验证。每阶段原始日志都核对 Pass / Failure / Error / Ignore 和完整结束标记；结果与包哈希见 `TEST_REPORT.md` 第 12 节。

2026-10-14 最终同一轮结果为 **8/8** 账号 / 双端场景及 **2/2** 独立测试库清理，全部 Failure/Error/Ignore 为 0。[阶段清单](test-results/2026-10-14-account-phases.json)逐条关联独立原始报告；[真实图集](design/account/README.md)含 10 张已经人工查看的原图。另已完成当前主包的存储 / 浏览 6/6、未登录状态 1/1、文明连线 2/2，以及本地 43/43、报告解析 9/9、HTTPS / SQLite 服务综合 1/1。

离线验证暂时停止的是本任务账号服务，期间两端到该服务的请求都不可达；脚本结束会恢复同一数据库 / 证书。它不代表整机断网、离线账号登录或离线冷启动恢复。跟进修正只更新旧未登录状态测试和离线说明注释，主包未改变；两版测试包的哈希与各自覆盖见测试报告第 12 节。

## 本机 API 核验

核验日期：2026-10-14，类型声明版本 HarmonyOS SDK 26.0.0.105。

| 接口 | 本机声明最小版本 | 使用范围 |
|---|---|---|
| `NetworkKit.http.createHttp/request/destroy` | API 6 | 原生账号注册、登录与实际交换 |
| `HttpRequestOptions.caData` | API 20 | debug 包信任任务专用公开 TLS 证书，继续验证主机名 |
| `HttpRequestOptions.body` | API 26 | JSON 请求体；按本机 API 26 声明使用 |
| `util.TextDecoder.decodeToString` | API 12 | 解码本机服务配置，避免弃用 `decodeWithStream` |
| `application.createModuleContext` | API 12 | 仅测试显式读取 entry_test 的私有测试资源 |
| UIAbility `onForeground/onBackground` 与窗口 `LocalStorage` | 既有 Stage 能力 | 前台才轮询，身份数据不使用全局 AppStorage |

HTTP 声明核对 `openharmony/ets/api/@ohos.net.http.d.ts`，官方入口：[HTTP API](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/js-apis-http)。本轮没有新增低版本兼容包或公开服务部署。
