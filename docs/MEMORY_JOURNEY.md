# Step 3：拾遗手账与主题漫游

记录日期：2026-10-17。目标工程：HarmonyOS 7 / API 26。

本轮已接入拾遗手账、主题漫游、路线纪念章和个人图谱中的主题路线展示。主包与测试包构建成功，单项核心设备演示通过；本文记录实现范围、真实展示路径和当前边界。

## 手账记录

手账沿用 `ArchiveRecord` 的 `kind: 'note'`，正文、标签、笔记 ID、逻辑时间戳、安装实例 ID 和删除墓碑继续使用原有格式。Schema 保持 v1，增加的四项元数据都是可选字段：

| 字段 | 保存内容 |
|---|---|
| `stampType` | 手账装饰印章：河洛拾遗、夏都寻踪、商都吉金、汴京梦华、仰韶初光 |
| `paperTheme` | 纸色主题：`rose`（玫瑰笺）、`ochre`（陶土笺）、`jade`（青玉笺）、`ink`（墨色笺） |
| `quotedPoemOrFact` | 用户选择带入的档案摘录；仅取当前档案已有摘要，摘要为空时取概览，最多 160 字，不生成诗词或新事实 |
| `snapshot3DPose` | 可重建的示意视角参数，不包含截图、遗址照片或模型像素 |

`snapshot3DPose` 包含 `version`、`sceneType`、`yaw`、`pitch`、`zoom`、`hotspotId`、`sectionId` 和 `label`。在详情视口点击“留住此刻 · 写一页手账”会读取当前视角，再打开手账编辑器。Web 绘制分支从视口当前状态读取相机值；保存后打开对应手账时，详情页恢复所选场景、热点或主题和相机参数。当前详情恢复支持器物凝视和主题切片，视角版本为 1 且场景类型相符才会应用；缩放会限制在视口支持范围内。恢复依赖同一程序化场景重建，不是打开一张截屏。

新建手账编辑器提供印章和四种纸色，默认印章按档案预设，初始纸色为玫瑰笺；摘录开关默认选中。用户保存后才把这些选项写入 note。印章只是装饰，不代表遗址断代、王朝归属、文物出土结论或实地到访。摘录继承档案本身“初稿待校审”的状态。时间旁的节气标签按本机日历的常见月日分段，始终标为“时令近似”，不是精确历法计算。

兼容规则和完整字段约束见[拾遗手账数据兼容说明](MEMORY_MIGRATION.md)。读取旧快照时不自动补印章、纸色、摘录或视角，也不更改旧笔记时间戳。旧普通 note 仍可在记忆列表中浏览；无显式印章时卡片显示“河流笔记”。只有用户进入编辑器并主动保存后，记录才会带上新元数据并参与手账判断。

## 记忆列表与画廊

“记忆”页的“云河拾遗手账”区域使用“列表 / 画廊”切换。手账区位于记忆统计之后、收藏档案之前，让新保存的记录优先出现在展示路径中。两种模式都展示所有未删除的 note，包括没有手账元数据的旧笔记：

- 列表卡片以紧凑排版显示正文三行。
- 画廊卡片显示正文八行，并增加纸面装饰。
- 卡片可展示档案城市与名称、显式印章或“河流笔记”、已保存摘录、时间与近似时令、标签和保存状态。
- 有视角参数时，凝视入口会携带该参数重新打开档案；旧笔记无视角时入口只打开遗址凝视，不伪称恢复了已保存视角。
- “打开档案”、凝视、编辑和删除是独立操作。删除沿用既有墓碑记录，不抹掉原 note 的扩展字段。

卡片的保存状态由页面传入：当前账号状态确认记录已同步时显示“已完成账号同步”，否则显示“已保存在本机”。本机保存和账号同步是不同状态，不能仅凭登录状态宣称记录已传输。

## 主题漫游与点亮规则

个人页原“教育计划”占位由主题漫游面板替代。大学和学号不参与路线、手账或探索进度判定。首页“黄河寻迹漫游”入口可到达个人页路线面板；路线面板展示进度、下一处节点，以及“查看图谱”入口。

路线节点仅引用文化目录的稳定档案 ID。当前定义三条主题阅读路线：

| 路线 ID | 名称 | 档案 ID 顺序 |
|---|---|---|
| `seeking-xia` | 寻夏记 | `smx-yangshao` → `smx-miaodigou` → `ly-erlitou` → `ly-yanshi-shang` → `zz-shang` |
| `earth-and-fire` | 泥火成器 | `smx-miaodigou` → `zz-dahecun` → `zz-duling-fangding` → `kf-iron-pagoda` |
| `folded-capitals` | 折叠的都城 | `ly-hanwei` → `zz-zhenghan` → `kf-zhouqiao` → `kf-city-wall` → `py-qicheng` |

某档案满足以下任一条件，就算路线节点已完成：

1. 四个阅读主题的显式探索进度达到 75%（通常为完成其中三个主题）；或
2. 存在该档案下未删除的有效拾遗手账。有效手账必须仍是 `kind: 'note'`，并且印章在支持列表中，或纸色在四种支持值中。

普通旧笔记、收藏、仅打开过档案的 `opened` 记录都不满足手账条件；旧笔记不会因为被列表展示而自动点亮。单个手账最多点亮它所属的一个路线节点，路线纪念章仅在该路线的全部节点都满足门槛时点亮。

路线进度和已点亮纪念章由当前快照中的真实记录重新派生，不另存永久完成标志。用户删除相关记录或合并后的有效版本变化时，路线状态随新快照重新计算。纪念章是展示状态，不会写入一条虚构的到访或完成记录。

## 路线图谱

从路线面板打开图谱时会带入路线 ID。图谱筛选到该路线所列的档案，并按路线顺序绘制主题连线，突出显示路线节点与当前探索状态；从路线筛选退出后，图谱恢复原有五城或个人模式。未选择路线时，纪念章入口和主题路线高亮只来源于已经全部完成的路线。

路线连线表达的是应用为阅读安排的主题关系，不表示年代先后、历史传承或因果关系，也不等同真实交通路线或考古地层。五城档案的文化内容仍为初稿待校审。个人图谱仍从用户已有档案和笔记派生；路线图形不会创造文化事实。

## 演示与当前验收状态

建议的核心演示路径为：打开一个文化档案，留住视角并保存手账；在“记忆”页切换到画廊，查看这张手账并通过凝视入口恢复参数；回到个人页路线面板，确认该档案节点进度变化，再从图谱入口查看主题路线。点亮完整路线徽章前，路线中每个节点都必须分别达到门槛；一条手账只完成其所属节点。

截至 2026-10-17，本地 **89/89**、报告解析 **9/9**，主包与测试包均构建成功。单项 `MemoryJourneyTest` 核心演示 **1/1**，Failure / Error / Ignore 为 0：通过真实 UI 保存手账，回读印章、纸色、摘录和视角，翻开画廊并恢复凝视参数，验证寻夏记节点点亮至 1 / 5，再进入路线图谱。四张实际页面见 [图集](design/memory/README.md)，包与报告见 [阶段记录](test-results/2026-10-17-memory-phases.json)。
