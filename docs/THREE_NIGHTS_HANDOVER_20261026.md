# 云河纪《开封三夜》开发交接

本轮基于 `324056c` 之后的工作区实施用户确认的“开封三夜”。原生 HarmonyOS 7 / API 26 工程继续使用 ArkTS / ArkUI。主入口已经是三夜经营；V1《汴京开市》、五城纸景、原22处文化档案和旧记忆仍有访问入口。没有自动提交、推送、发布或改动用户签名。

实际包关系、逐条设备 Pass / Failure / Error、保留失败和截图以[测试第37节](TEST_REPORT.md#three-nights-20261026)、[机器清单](test-results/2026-10-26-three-nights.json)和[原生画面](design/three-nights/README.md)为准。玩法讲解见[五分钟演示指南](THREE_NIGHTS_DEMO_20261026.md)，引用与能力核对见[本轮研究](research/three-nights-20261026.md)。旧交接与测试第36节保留其原有版本含义，不能替代本轮结果。

## 玩家实际经历

每夜四段，每段三批。开段只确定本段照明和扣灯油，领域层每次只结算下一批；前两批后暂停，玩家看见已发生的去向后决定是否使用应急。第三批保存后，明确收段才结工钱和铺租。回放从已确认保存的当批结果取来客、偏好、目标铺、实际成交和受阻街区；动画不推进经济。

准备阶段可以开铺、收铺、分伙计、选灯和走两趟常规补货。营业后每段共两次应急：调一人、急送一包、移动已亮街灯；第二夜起可改派已出发的巡茶人。急送按常规价格1.5倍向上取整，不占两趟常规补货；调人不退接待名额，移灯不增加灯数、不返还已耗灯油。资料、应急面板和后台会暂停回放，不按反应速度扣分。

| 夜次 | 新的取舍 | 新夜预算 / 目标 |
|---|---|---|
| 州桥初市 | 集中布铺便于安排，但中街会拥堵；分散铺子又要分六名伙计。 | 60游戏钱；接待至少65客，收市至少余20钱。总来客100。 |
| 夜深归人 | 茶铺与提瓶巡茶争用人手。巡茶最多占一人，每批最多服务指定街区两位茶客，真实消耗茶料。 | 70游戏钱；接待至少65客，其中茶客至少30，至少余20钱。总来客108。 |
| 元夜灯市 | 灯棚占铺位与一名伙计，需实际照明。观灯客先去灯棚，再寻找饮食；两步都完成才计专项目标。 | 90游戏钱；接待至少65客，其中至少24位观灯后消费，至少余20钱。总来客108。 |

三夜依次开启。新夜首次建立时复制前夜已确认的铺位、人手、计划灯位与巡茶区，预算和基础库存重新发放。失败只重开当前夜；重玩采用本夜已确认布局。已经建立的合法后夜不会被前夜重玩重新锁住，也不会被追改布局。

每夜均有三街均来、西来客多、东来客多三套公开路线，重玩前展示差异并明确确认，不在局内暗改需求。`NIGHT_CONFIGS`、`NIGHT_ROUTES`、物资与价格集中在领域文件；当前关卡修订为1。领域策略验证包含3夜×3路线×2种公开动作方案，不把这18种领域运行写成18次原生真人试玩。

## 文化、收藏与记忆

三篇新增文献使用独立身份：

- `culture-kf-night-market`：《州桥南去，夜市初开》，卷二“州桥夜市”。
- `culture-kf-bottle-tea`：《三更以后，提瓶卖茶》，卷三“马行街北诸医铺”。
- `culture-kf-lantern-festival`：《御街灯起，游人已集》，卷六“元宵”。

文化库分别统计22处遗址与3篇新增文献，保留五城、年代、类型、关键词与收藏分类。文献可直接阅读、分类收藏、选摘、写普通笔记，不靠通关或答题解锁。真实 `opened`、收藏和个人标签用于后续阅读推荐；经营 progress 不当作阅读比例、到访或收藏。

《东京梦华录》的语境为孟元老南宋追记北宋。卷六两条短引来自不同位置，保存来源标明“另一处短引”。三夜是原创生活情境编排，不宣称连续三日的历史复原；六铺地图、数值、灯棚容量、巡茶规则和观灯后消费规则均属原创游戏设计。资料保留“初稿待校审”，没有打包参考网页图片。

收市后可“写这一夜的记忆”；尚未通关时，资料面板也可主动“记下这一刻”。只有用户确认正文或摘录才创建 note。冻结时包含夜次、内容与图景修订、路线、当前段与批、六铺类型和人手、街灯、巡茶区、经营摘要、摘录与完整来源。营业中的灯使用实际 `effectiveLamps`，备市与收市使用保留的布置。以后经营、改建、重玩和资料修订都不改变这篇保存时依据。

平板资料与草稿并列：API26 `SelectionContainer` 跨 Text 选摘后生成卡片，再经 UDMF 拖到草稿。手机用可滚动原生底部半模态。普通文献笔记继续支持正文、标签编辑及回到原文献；冻结经营记忆有独立正文、图景与出处页，编辑只改个人文字与标签。

经营独立记录为 `progress:river-market:v2:kaifeng:<nightId>`，文化关联仍为 `kf-zhouqiao`。V1记录原样保留，不迁移成三夜达标。V2正文采用紧凑codec，不存逐客坐标和动画轨迹，完整策略检查点最大1690字符，低于现有4000字符限制。

接口为 `createMarketNight`、`beginMarketNightRound`、`advanceMarketNightBatch`、`applyMarketNightAction`、`endMarketNightRound`。begin、每批、每次应急和end各自先落检查点，保存失败只重存同一冻结版本，不重算经济。页面用编辑代次和确认代次识别回执，Root排队时从最新快照产生逻辑时间戳；后台、退出和冷启动不补算离线营业。

**格式兼容不需一次性迁移脚本。** 外层仍为schema v1，note只新增可选 `marketContext v1`。已贯穿校验、深拷贝、确定性版本比较、Repository、JSON备份表达和HTTPS。旧note没有该字段时不补写，不改旧ID、时间、装饰、pose、纸景作品、漫游上下文与AI冻结依据。扩展或经营正文损坏时保护原记录，不能静默剥字段后覆盖。删除保留墓碑。

同夜经营在多端间按完整版本选择，不能把库存、钱和接待人数跨端相加。外端不同版本到达时提供主动采用，不覆盖当前应急选择或笔记草稿。账号身份切换继续隔离；游客只有明确选择“复制漫游”才把相关记录带入账号，本机原副本保留。

## 系统能力与验证边界

“继续经营”是普通2×4 FormKit卡片，来自已确认夜次和批次；点击恢复对应检查点，不自行推进。分享由用户主动调用ShareKit，生成带冻结图景、摘录、感想和出处的原生PNG和文字；取消不改记录，系统面板出现不代表第三方收到。

实际双端继续为**自建账号HTTPS**。本机原生KV版本库、设备查询与HTTPS是不同能力；华为账号、鸿蒙原生可信设备传输及系统应用接续仍须支持设备另行验收。完整文件备份恢复也没有因可选字段JSON往返而自动完成。

性能采样只有Debug独立测试库显式开启。静态街市和逐客动态层分开；静态缓存按视觉输入变化，定时回放不逐帧更新整页State。`MARKET_NIGHTS_PERF`记录绘制命令CPU、连续定时回调间隔、首回调等待、首次静态缓存、后台和资料/隐藏暂停。回调间隔不是屏幕FPS，命令CPU不是GPU完成耗时。真实采样与限制见第37节。

## 后续开发与操作

先按演示指南真人试玩，重点观察：是否看懂离开原因、是否愿意为后果取舍、是否想换安排再玩。4—6分钟单夜和五分钟展示目前属于设计目标，自动化耗时不能代替真人计时或趣味结论。本轮范围不扩五城经营、多人协作或无尽科技树。

必要检查保持：`tools/test.ps1`、`tools/build.ps1`，触及页面/存储时运行对应设备专项。三夜分阶段测试必须显式传 `-MarketNightsStore yunheji_test_ui_nights_<本轮标识>`；三个阶段共用该独立库，只有最后明确清理case才删它。同步fixture只属于ohosTest，先私备再生成；两端和返程使用同一fixture，验收后恢复原源文件，不改HAP时间绕过新鲜度保护。

当前包与本机试玩入口见机器清单和私有 `.local/three-nights-20261026/`。旧Word/PDF、演示录像及现场包继续保留；本轮新增演示指南，不覆盖旧交付材料。后续更新赛事材料时，应使用本轮实际原生图和能力结果，避免把旧自动脚本当成三夜演示。
