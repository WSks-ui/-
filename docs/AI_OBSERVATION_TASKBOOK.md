## 2. 产品范围与体验

### 2.1 必须形成的主线

| 步骤 | 用户行为 | 可见结果 |
|---|---|---|
| 进入问题 | 首页直接进入方鼎观察，或从原详情打开“陪我观察” | 问题与方鼎同屏，已有热点仍可手动操作 |
| 自由提问 | 输入“我只数到了四个，另外四个在哪？” | AI依据本对象资料解释，提供“看四个折角”操作 |
| 聚焦观察 | 点击回答中的聚焦操作 | 原生模型聚焦 `corners`，选中标签和解释对应，用户仍可转动 |
| 继续追问 | 输入“跨过转角的这一组会不会算两次？” | 结合前文作针对性解释；不能只重复预置问答 |
| 检查依据 | 点击本次回答的依据入口 | 原生区域展示支持该解释的事实、来源名称与核验日期 |
| 留下发现 | 用户写一句自己的观察，再点“整理为手账” | AI生成可编辑短草稿；事实摘录与用户正文分别展示 |
| 确认保存 | 用户修改或采纳草稿，确认保存 | 实际视角、个人正文与 AI 参考信息落盘，首页出现真实记忆 |
| 跨端重访 | B端同账号收到手账并点击画面 | 正文、参考信息、预览可读，恢复实际保存部位和角度 |

用户自由输入是主要能力，三个起始问题只帮助开始。固定演示回复、关键词命中后播放预设台词、伪造流式文字不能计为 AI 接入。

### 2.2 页面要求

- 沿用现有 HDS 导航、Dock、独立“我的”、纸页与沙盘。首页在现有主题区域增加一个明确的方鼎问题入口；“泥火成器”的原按钮仍进入真实下一节点，保留完整四节点和原点亮规则。
- 在方鼎详情新增可收起的原生观察面板。回答就近关联当前模型，证据可原地展开；不另建全屏通用聊天首页，不要求为看依据返回首页。
- 输入、发送、停止等待、重试、依据和聚焦入口可操作。用现有系统 Symbol 表达适合的工具动作，页面不显示请求ID、JSON、供应商参数等调试内容。
- 模型、回答、输入框和键盘之间保持可用空间；检查常规手机上的实际画面，按本次路径修复遮挡、过长回答或滚动问题，不扩展大字和全设备矩阵。
- 回答区区分“AI参考解读”与原始资料；档案保持“初稿待校审”。程序化位置标记仍是学习示意，不变成兽面纹摹本或实物复原。
- 第一版采用点击建议后聚焦。回答到达不抢走用户正在操作的镜头；AI不得自动保存、删除笔记或标记路线完成。

### 2.3 暂缓事项

本阶段不做数字人、语音输入/朗读、拍照识物、AI生图、通用百科问答、自然语言检索全部个人记忆、个性化全城路线、多 Agent 编排、向量数据库或模型微调。这些是后续候选，不作为本阶段依赖。

不重写引擎、不降级HarmonyOS版本、不改成网页、不扩展城市与徽章；公网部署、会话生产化、华为账号、分布式KV和备份恢复沿用既有待办状态。跨端继续表示同账号个人信息同步。

## 4. 知识与模型契约

### 4.1 首版知识范围

从现有 `MaterialStudyCatalog.ts` 读取 `zz-duling-fangding` 的 `duling-object`、`duling-size`、`duling-eight` 及 `museum-duling-two`，不要另写一份容易漂移的事实正文。动作仅使用 `DulingObservation.ts` 的 `centers / corners / frame`，场景为 `duling_fangding / revision 2`。

模型输入包含当前对象、当前选中热点、用户问题、有限轮数的本次上下文和对应已核事实。首版可直接提供该对象全部三条事实；不必先实现语义检索。服务端根据已知ID组装资料，不把客户端自带正文当作权威来源。

必须区分：

- 资料事实：器物身份、尺寸、上腹纹饰位置等已收录陈述。
- 场景说明：玫瑰标记、陶色折片、镜头和简化几何等应用表达。
- 个人表达：用户主动输入的观察与感受。

模型只能在这三类信息各自的范围内解释。没有资料支持的纹样寓意、祭祀对象、制作细节或其他文物信息，应说明当前资料不足；不编写来源，不凭器形推导传承关系。有效来源ID不等于整段回答正确，固定小样仍需逐条人工核对语义支持。

### 4.2 拟定请求与响应

以下是应用自己的接口草案，不是已经存在的接口，也不是某家模型API的原样请求。

| 方向 | 字段 | 含义 |
|---|---|---|
| 请求 | `version / requestId / siteId / sceneRevision / hotspotId` | 协议与当前观察上下文；请求ID用于区分并发和迟到回复 |
| 请求 | `purpose` | `observe` 或 `draft_memory`；生成草稿必须由用户主动发起 |
| 请求 | `question / turns` | 当前问题和有限轮数的本次对话，不上传全部个人档案 |
| 请求 | `userObservation` | 仅整理草稿时提供；为空时先请用户留下一句观察，不虚构个人经历 |
| 响应 | `version / requestId / siteId / contentRevision` | 服务端设置并校验，不依赖模型猜测身份或版本 |
| 响应 | `status / answer / factIds` | `grounded`、`needs_clarification`或`insufficient_evidence`；短解释与引用事实ID |
| 响应 | `actions` | 下表允许的操作建议；对象、热点、事实必须属于本次上下文 |
| 响应 | `draft` | 仅草稿请求返回：建议正文、建议标签、参考事实ID；不含自动保存指令 |

| 操作 | 参数与执行规则 |
|---|---|
| `focus_hotspot` | 参数为合法 `hotspotId`；客户端按现有推荐镜头聚焦，不让模型直接生成相机、几何或脚本 |
| `show_evidence` | 参数为本对象合法 `factIds`；从应用资料生成事实卡与来源入口，不使用模型生成的URL |

拟新增 `POST /ai/observe`，沿用现有账号服务身份。游客可继续本地探索；首版仅已登录账号使用在线AI，提示保留当前页面，不强迫游客退出观察流程。该路由已于 2026-10-18 接入；鉴权后、`/sync` 前分派，不占用同步事务，按账号限流。

AI01核实一种能稳定返回上述结构的调用方式即可：结构化输出或函数调用均可，适配层统一成应用契约，不同时搭建两套工作流。`factIds`与`actions`需经过应用规则校验；不满足契约的响应进入失败/重试状态，不能将未校验的模型文字直接当成可执行内容。

### 4.3 模型配置与等待状态

- 本阶段实际采用 **DeepSeek 官方 API / `deepseek-flash`**（2026-10-18 核验）。OpenAI 兼容 `POST https://api.deepseek.com/chat/completions`，强制函数调用 `submit_observation`，关闭思考模式；服务端超时 20 秒，客户端 AI 读超时 25 秒。最初试过 JSON 文本模式，多轮上下文下出现空白内容，已改为函数调用；不能把“结构可解析”当成事实正确。接入说明见 [AI_OBSERVATION.md](AI_OBSERVATION.md)。
- 密钥只在服务端环境或已忽略本机配置中；客户端只连接项目后端。不得将密钥写入HAP、Git、日志或截图。本任务书不涉及购买额度或公开部署。
- 首版短回答建议控制在约80—180个汉字，资料正文按需展开。记录实际等待时间，再调整输出长度与超时；不预填“秒回”或可靠性百分比。
- 状态至少包含未配置、需登录、等待、成功、资料不足、网络/服务错误。停止或离开后，迟到回复不得覆盖新问题、新对象或新账号的页面。
- 保留输入和用户草稿。未配置或调用失败时显示真实原因，本地热点、原始资料和手写笔记继续可用；不把静态解释标为实时AI结果。
- 当前账号客户端请求读超时为10秒、服务端 `requestTimeout` 为15秒。AI02须核对模型调用、原生请求和代理的各层等待/取消行为；不要直接假定账号请求配置适合模型生成，也不要为AI无差别放宽所有同步请求。

## 6. AI手账与兼容要求

建议沿用 `schemaVersion: 1`、`kind: 'note'` 和现有记录身份，新增可选 `aiAssist`。AI01 已确定最终字段名（`version / question / factIds / contentRevision / facts`），AI04 已更新 [MEMORY_MIGRATION.md](MEMORY_MIGRATION.md)；本任务书本身不修改格式。

| 拟定元信息 | 用途 |
|---|---|
| `version: 1` | AI参考元数据版本 |
| `question` | 用户选择保留的本次问题，不保存整段对话 |
| `factIds` | 用户采纳草稿时使用的参考事实 |
| `contentRevision` | 当时资料版本；首版应保留对应的冻结事实版本可供解析 |
| `facts` | 采纳时冻结的事实快照（id/title/body/sourceIds），资料日后修订仍可显示当时依据 |

字段含义是“这页曾参考AI辅助整理”，不认证用户最后编辑的每一句都由资料证明。只有采纳或修改AI草稿后确认保存才写入；只问答后手写、放弃草稿、生成失败均不补标。

正文由用户确认；`quotedPoemOrFact`仍取资料原文，不装入模型生成的历史结论。保留现有 `snapshot3DPose`、印章和纸色。用户手写草稿已经有内容时先显示建议供采纳，不异步覆盖正在输入的文字。

AI04必须一起处理：

1. `parseSnapshot`：校验新增元数据形状；损坏时沿用读取失败保护，不删字段后静默覆盖。
2. `copySnapshot`及编辑/删除路径：深拷贝新增数组，保留元数据；注意 `SiteDetail.saveNote`当前逐字段重建记录，单改接口不能保证编辑后仍保留。
3. `recordContent / compareVersions / mergeRecords`：新字段参与确定性内容比较，原删除墓碑和冲突规则不变。
4. 本地保存、服务端解析、HTTPS交换和B端显示：使用同一协议；更新后端运行进程以加载新规则，两端使用新包。
5. 旧普通笔记及旧手账：缺省字段保持缺省，不补造AI来源、不批量改时间戳，不改变旧revision 1回放。
6. 资料版本暂不可解析：保留问题、原引用ID、正文和视角，明确显示依据版本暂不可读取；不能套用新资料宣称原依据已恢复。

迁移采用可选扩展时无需批量重写旧记录，但必须说明旧客户端可能丢弃新字段，不能宣称新旧版本双向无损。回退前保留完整快照，不清库、不复制安装实例身份。本阶段验证新包双端与新客户端读取旧记录即可，不展开完整历史客户端矩阵。

### 7.1 小范围真实模型评估

使用下列固定小样逐条记录输入、实际模型、资料修订、回复、引用、动作、耗时与人工判定。不比较固定措辞，不用“JSON可解析”替代内容正确。以下是预期行为，不是已取得结果。

| 问题/操作 | 预期 |
|---|---|
| “只有四面，八组是怎么数出来的？” | 解释四壁正中与四折角，引用 `duling-eight` |
