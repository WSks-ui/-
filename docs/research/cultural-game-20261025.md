## 4. 独立候选循环：先解释，再主动找能推翻解释的地方

这一节是独立研究候选，未作为已采用产品方案。主代理随后确定的“纸上生城”方向及其依据边界见第6节。

主界面是一处可走近、切换侧面和资料视图的原生场景，承载玩家画在景上的观察与推论；不是答题页，也不叠加一排线索卡。每城以一个真实的解释冲突开场，玩家在调查过程中形成一份可撤销的个人解释。

1. **看见异常。** 例如一段石壁消失在更晚建筑后方，或同一洞窟两部分资料年代不一致。开场提供现象，不把“正确放法”写在说明里。
2. **自己选择调查动作。** 到侧面看遮盖关系、把观察范围从整洞缩到造像、沿遗址分布比较另一区域、查看已知材料的记录时间。每种行动给不同信息；“多拖几次”不产生证据。
3. **留下临时解释与预测。** 在原景上圈出范围、画连接、记“暂认为同代/后加/尚不能定”，随时改或撤回。至少有一条可检验预测，例如“如果整洞一次完成，洞体与造像的对应年代应相同”。
4. **执行一次检验。** 玩家决定去找什么可能推翻它。新观察与解释冲突时，只指出冲突的局部和来源，不自动亮出完整答案。修正范围或关系后，调查路线继续，已经发现的可靠材料不会因改判消失。
5. **留下真正属于自己的发现。** 用户确认后保存“我看到了什么、曾怎样解释、什么证据让我改判、还有什么不知道”，连同冻结出处形成普通个人笔记；自由收藏和任意手写继续可用。五城扩展靠新文化关系，不靠更多等级、工日或通关卡。

开封可以先检验“明桥为何遮住更早石壁”这一案，完全取消桥位拖放；从正面整体印象走到遮挡边界，再看两侧编号所属文本，建立有范围的分期解释。洛阳则必须分开处理洞体与造像，不能沿用开封的覆盖顺序规则。濮阳允许证据不足时停在未知，不把所有问题设计成唯一姓名答案。

这一循环的乐趣来源是预测落空后“原来我把两个不同范围/年代当成了一件事”，不是系统宣布记住一个知识点。它仍须先做一案可点击的原生小样，验证玩家是否会主动改判；本文没有把机制提议当作已验证的好玩结论。

## 5. 首案成立条件与尚缺材料

- 不读说明背答案也能通过观察建立至少两种不同解释；至少一种解释会被后续可见材料推翻。
- 移除文化事实后，玩家的有效行动和结论必须改变；否则仍是文化命名包装。
- 错误解释不清空成果，撤销推论与重新观察必须便捷；系统不因访问热点数量自动通关。
- 结算能够指向玩家实际采用及忽略的证据，而非只有等级或完成动画。
- 公开资料只支持本研究列出的关系。精确遗址图、逐件照片/题记、图像授权仍须逐案补齐；原创建筑或分布示意应明确说明范围，不能用模型生成“考古原照/原刻”。
- AI如加入，应围绕用户当前解释询问“还缺什么反证”，引用本案已核材料；不替玩家选择调查路径、不揭示隐藏答案、不把随机局面当史实，也不把关键词校验描述为自动史实审定。

本轮没有更改产品、重新测试或验证跨端。后续原生实现仍按项目约定运行 `tools/test.ps1`、`tools/build.ps1`，并围绕实际演示路径取得设备结果。
