# 开封“叠城寻路”：本轮实现与边界

日期：2026-10-23。本文记录 `docs/GAMEPLAY_REDESIGN_HANDOVER_2026-10-23.md` 第一批交付的实际落地情况，
与设计意图分开写：这里只写**已经跑通的**、**明确没做的**和**怎么复核**。

## 1. 做了什么

### 1.1 纯领域规则（可脱离 UI 回归）

新增 `entry/src/main/ets/domain/KaifengPuzzle.ts`（429 行，不 import `@kit`、UI 或存储）。
它把旧版塞进一个 `amount` 的状态拆成可判定的结构关系：

| 输入 | 判定 | 输出 |
| --- | --- | --- |
| 桥心坐标 + 朝向 | 北端/南端是否落在街口岸线；是否跨过水面；是否顺河躺在水里 | `solved`、`streetOpen`、`waterOpen`、`verdict`、具体断点 `personStop` / `boatStop` |

关键设计：

- **不再用阈值判完成。** `solved` 只由端点几何关系决定，动画时长、提示次数、点击次数都不参与。
- **三种失败各自可解释**：`along-river`（顺河躺在水里，船过不去）、`north-only` / `south-only`（只接通一端）、
  `offset`（跨过了河但没对准街口）、`on-bank`（还在岸上）。
- **吸附不替玩家解谜**：`settleKaifengBridge` 只在已经接近时吸附（角度 ±7°、街心 46 单位内），
  远处拖动不会被拉向答案；开局坐标 `(706,214,24°)` 经测试断言为未解状态。
- **数值是玩法参数**：桥长 200、河宽 130、街宽 60、容差 28/64 均为原创示意参数，
  不对应州桥形制或汴河断面，正文里也这样写。

第二段（同址多期）与第三段（制灯）同样在规则层：

- `placeKaifengEvidence`：材料片锚点距离 ≤64 才算叠合，否则退回；三份齐了给出“同一位置、不是同一年”。
- `judgeKaifengInterpretation`：三句解释里只有一句同时满足“同址”和“异时”，另两句各错一半。
- `validKaifengLantern`：只校验骨架/纸面/位置属于原创模型选项，**不规定唯一审美**。
- `KaifengWorkV1` + `parseKaifengWork` / `serializeKaifengWork`：版本化作品快照，
  缺字段或版本不符一律返回 `undefined`，不把残缺数据补成看似正常的桥位。

### 1.2 关卡组件

新增 `entry/src/main/ets/components/KaifengPuzzleScene.ets`（527 行，原生 Canvas + 手势）。

- 画布与热区共用**同一套等比缩放与居中**（`unit()` / `originX()` / `originY()`）。
  最初的实现让画布按 x 比例、热区按另一套比例，桥画在一处、能拖的是另一处；已修正。
- 单手完成：拖桥片平移；拖铜环（东端手柄）绕桥心旋转；两指旋转没有做，也不作为门槛。
- 画面即反馈：人停在断点画 `×`，船被堵停在桥前，成立后两人分走两端、船从桥下出来。
- 桥面起拱、桥台、桥墩与桥下水影，避免读成“压在河面上的直板”。

### 1.3 接进篇章页

`RoamingChapterPage.ets` 只加分支，不重写编排：开封走 `KaifengPuzzleScene` + `kfControlPanel()`，
其余四城仍是原 `RoamingScene` + 原面板。共用部分抽成 `clueOptions()`。

- 完成门槛改为 `interactionReady()`：桥段要求 `judge.solved`；资料段要求三片叠齐 **且** 选对解释；
  制灯段要求已点亮。
- 提示三级：指出街 → 圈出交会处 → 演示一次摆放；演示后画面与按钮都标注“不算你独立解出”。
- 按钮文案跟随玩法状态（“先让桥两端接通 / 先把三份材料叠上去 / 先选一句能解释的说法 / 先点亮这盏灯”），
  不再沿用旧记录的“继续下一条线索”。

### 1.4 内容

`data/RoamingCatalog.ts` 中开封三条线索改写为目标、指令与正文，`ROAM_CONTENT_REVISION` 由 1 推进到 2。
旧记忆保留各自冻结的 `contentRevision=1`，不追改。文化边界写进正文：
州桥“现发现桥体为明代早期、在宋代桥基基础上建造”；北宋灯事与清末灯彩分标年代；原创纸灯不称非遗工序。

### 2.2 设备实走（API 26 手机 1256×2760，`127.0.0.1:15555`）

按顺序真实点击/滑动，节点状态取自 `uitest dumpLayout`：

| 步骤 | 实际观察 |
| --- | --- |
| 进入开封 | 桥在岸上，读数“尚未接通”，提示“桥还搁在岸上，两端都没有搭到街口与水面之间。” |
| 拖桥到街口但不转向 | 读数“水路被堵”，船停在桥前并出现断点叉 |
| 拖铜环转向过位 | 读数“只接通一端”，反馈“南岸接上了，北端没有搭上岸：街上的人走不到桥头。” |
| 提示三级 | 街高亮 → 交会处圆环 → 演示摆放；出现“这一次是提示演示的摆放，不算你独立解出。” |
| 关系成立 | 读数“两条都通了”，按钮“确认这一段，继续”由禁用变可用 |
| 三片材料拖到桥位 | 读数 `1 / 3 → 3 / 3 材料`，出现三句解释 |
| 选错解释（同一时期） | 反馈“位置对得上，年代对不上”，按钮仍禁用并显示“先选一句能解释的说法” |
| 选对解释（同址异时） | 反馈“位置相同、年代不同”，按钮启用 |
| 制灯 | 换骨架/纸面/位置即时重画，点灯后读数“已点亮” |
| 收束 | “收好这一城的故事”可用，结尾面板出现 |

旧数据观察：本机仍保留旧版 3/3 进度，页头显示“已展开”，但确认按钮在未解时**不可用**——
旧 `progress:roam:v1` 没有绕过新规则。正式演示机若从零开始不会出现这两个旧标记。

## 3. 明确没做

1. **作品持久化没接。** `KaifengWorkV1` 已定义并有往返测试，但本轮只存在于页面内存；
   没有写进 `ArchiveRecord`、没有参与 `copySnapshot` / `mergeRecords` / HTTPS 同步 / 预览。
   因此现在**不能**说“已经保存了你的桥位与灯”。记忆笺保存的仍是片段与亲笔正文。
2. **材料片不是 UDMF 系统拖拽**，是组件内 Pan 手势。系统拖拽进证据区、平板上跨窗口拖卡都未做。
3. **平板未复验**：横竖屏切换、三栏 ≥1000vp 下新关卡的表现没有重跑，不引用旧平板截图。
4. **其余四城未改机制**，仍是原图景与原阈值流程（按交接文档，等样板好玩后再各做一种）。
5. **没有真人试玩。** 上文只说明“功能已实现、原生操作已走通”，
   不能替代“玩家是否理解、是否觉得有趣”。
6. 触觉反馈未接（可选项目，模拟器不可感知）。
