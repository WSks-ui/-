# 拾遗手账数据兼容说明

记录日期：2026-10-17。目标工程：HarmonyOS 7 / API 26。此说明对应 Step 3 的领域数据格式，界面、真实设备与双端结果由本轮测试报告另行记录。

拾遗手账沿用 `ArchiveRecord` 的 `kind: 'note'` 和 `schemaVersion: 1`，不改已有笔记 ID、正文、标签、更新时间、安装实例身份或 Preferences 名称。新增的四个字段均为可选值：

| 字段 | 格式与含义 |
|---|---|
| `stampType` | 印章装饰主题字符串；当前支持河洛拾遗、夏都寻踪、商都吉金、汴京梦华、仰韶初光 |
| `paperTheme` | 纸色字符串；当前支持 `rose`、`ochre`、`jade`、`ink` |
| `quotedPoemOrFact` | 用户保存时从档案已有摘要或概览摘录的文字；默认最多 160 字，不生成未经核实的诗词或新事实 |
| `snapshot3DPose` | 示意视角对象，包含 `version`、`sceneType`、`yaw`、`pitch`、`zoom`、`hotspotId`、`sectionId`、`label`；不是截图、实景图或考古复原文件 |

本次采用按需扩展：旧快照可直接读取，缺少手账字段的普通笔记保持原样，读取和复制不会补上默认印章、纸色、摘录或视角，也不会更新其时间戳。旧笔记可以在记忆列表里展示；只有活跃笔记显式包含受支持的印章或纸色之一，才由 `isMemoryPostcard` 计作手账。用户主动保存为手账后，界面才写入所选元数据，并按既有逻辑时钟更新记录。

新客户端的 `parseSnapshot` 检查可选字符串与视角字段形状，保留合法值。未知印章、纸色与场景字符串仍可归档保存；界面是否能够显示或重放由对应支持名单决定，不能把未知场景误称为已恢复视角。视角版本为正整数，角度与缩放必须为有限数值，缩放为正数；空热点和空主题表示未选择细分位置。损坏数据沿用现有读取失败保护，不能因新字段解析失败而清空原档案。

`copySnapshot` 深拷贝视角，编辑草稿不会改变已保存数据。确定性版本比较按固定字段顺序比较全部手账元数据，因印章、纸色、摘录或视角产生的跨设备差异也可返回落败冲突版本。时间戳、删除优先和设备 ID 的原有裁决顺序继续保留；删除仍是原笔记的墓碑，不删掉记录或其元数据，迟到的旧版本不能复活它。

升级前无需批量迁移，也不复制或重建安装实例 ID。既有 `previous_snapshot` 仍是落盘保护副本，不能当成新增的一键恢复功能。若需回退应用版本，应先保留包含新字段的完整快照，并让参与手账同步的设备使用本轮或更新客户端：未升级的旧客户端只复制旧字段，在编辑或保存快照时可能丢弃手账元数据，因此**不保证旧客户端保留新字段**。现有账号服务复用领域解析与合并，但旧运行进程仍需重启以加载更新后的规则；本说明不代表当前双端已复验。

时令标签采用记录时间在本机日历中的常见月日分段，始终显示“时令近似”，不作为精确节气历法。印章名称是可切换的手账装饰主题，不替代档案的断代、王朝归属或器物出土结论；摘录继承对应档案“初稿待校审”的内容状态。
