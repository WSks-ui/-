## 1. 项目目标

作品名：**云河纪**。

参赛材料建议名称：**云河纪：黄河文化分布式数字档案**。

目标用户：学生与文化爱好者。主场景为日常浏览黄河文化、出游或研学时查看资料、收藏感兴趣的内容并留下个人记忆；更换设备后，登录同一账号即可访问同步的个人信息，不要求在另一端继续整理工作。

核心路径：

```text
浏览/检索文化内容 -> 查看档案 -> 收藏或记录感受
同一账号登录其他设备 -> 同步个人信息 -> 按自己的需要继续使用
```

第一轮任务是搭可扩展的原生基础，不是完成全部赛题，也不是制作网页概念稿。

跨端同步范围包括收藏及分类、笔记及标签、浏览记录、阅读状态和适合跨端共享的个人偏好。个人图谱从同步后的收藏/笔记派生，不是独立的协作项目。完整阅读进度尚未实现，当前访问记录只有 `opened`；不得把计划同步的范围写成已经完成。

| `domain/AccountSync.ts` | 账号状态、身份与响应校验 | 无平台依赖；账号 ID 来自已认证服务，不用安装 ID 代替 |
| `data/HeritageCatalog.ts` | 文化种子内容 | 稳定 ID，不随名称改动；来源逐项补全 |
| `data/LocalArchiveRepository.ets` | Preferences 读写与落盘 | 保持 load/save 契约，迁移必须可回滚 |
| `sync/SyncGateway.ts` | 同步契约与不可用实现 | 没有真实接入时不得返回成功 |
| `sync/AccountSyncClient.ets`、`server/account-service.mjs` | 原生 HTTPS 客户端与独立账号服务 | 账号库隔离、先落盘、保留墓碑 / 冲突版本；不冒充华为账号或分布式 KV |
| `platform/HarmonyEffects.ets` | 新 API 隔离与降级 | 不让 SDK 新能力渗入领域层 |
| `pages/Index.ets` | 顶层状态、路由、首页/收藏/设备视图 | 当前是基础版；新增大型功能时再拆视图模型 |
| `components/SiteDetail.ets` | 详情、收藏、笔记编辑 | 编辑稿先本地，落盘后再发布 snapshot |
| `components/SiteRow.ets` | 统一档案行 | 标题/理由更新不能依赖未观察的普通属性 |
| `components/CultureAtlas.ets`、`CultureGraph.ets` | 五城/个人图谱、原生连线与对照 Sheet | 共用 snapshot 和详情路由；图形是关联示意，不是地理地图 |
| `resources/base`、`resources/dark` | 图形、文字、颜色 | 日夜资源 key 一致，不写死白字配浅色按钮 |
| `src/ohosTest` | 平台/界面测试 | 独立测试数据，不清空主档案 |

状态流：

```text
页面操作 -> 克隆快照 -> 领域规则构造记录 -> Repository.save
        -> flush 成功 -> 顶层替换 snapshot -> 界面更新
        -> 失败 -> 原 snapshot 保留，草稿不清空
```

第一轮没有接入后端或账号服务。后续依据同账号多设备同步需求接入真实登录、身份隔离和数据传输；不把“不引入账号服务”作为产品限制，也不以设备发现或安装实例 ID 代替账号身份。

## 5. 数据约定

### 5.1 快照

`schemaVersion=1`，字段为 `deviceId`、`records`、`lightEnabled`、`reducedMotion`。

Preferences 名：`yunheji_archive_v1`；当前快照键 `snapshot`；前一快照键 `previous_snapshot`。

当前备份是本地写入保护，不等于跨设备备份。读取损坏时阻断并提示，不擅自恢复旧快照，更不清库。用户可操作的恢复流程需下一轮设计。

### 5.2 统一记录

| 字段 | 约定 |
|---|---|
| id | 收藏 `favorite:<siteId>`；访问 `progress:<siteId>`；笔记 `note:<deviceId>:<time>` |
| kind | `favorite` / `note` / `progress` |
| siteId | 稳定关联离线条目，不依赖显示名称 |
| body | 笔记正文或 opened；最大 4000 字符 |
| tags | 字符串数组；最多 20 个，每个 <=40 字符 |
| updatedAt | 安全整数毫秒值，单机取 max(当前时刻, 已存最大值+1) |
| deviceId | 随机安装实例 ID，不是华为账号或硬件识别码 |
| deleted | 删除墓碑，查询时隐藏，同步时不能丢弃 |

首轮 `parseSnapshot` 校验格式、类型、记录数量上限和 ID 唯一性。不是网络安全验证完整替代；未来传入同步数据仍需身份、大小、来源、时间范围校验。

### 5.3 冲突顺序

先比较 `updatedAt`；相同时间删除优先；其次 `deviceId`；最后按规范字段内容稳定比较。

该规则保证当前记录值决策可交换、幂等，**不等于协同编辑算法**。时钟错误可能影响“最新”的含义；冲突返回也只是候选历史，没有向量时钟来证明并发。

不得在新设备恢复时无条件沿用旧设备 ID。旧备份迁移和多设备复制必须重新设计安装身份与账号归属。

## 6. UI 与鸿蒙特性要求

- 原生 ArkUI，不用 WebView 或 HTML 样稿代替移动端体验。
- 首屏即用，搜索与档案是主体，不添加宣传落地页。
- 使用 HarmonyOS Symbol 图标、原生 Select/Toggle/Sheet、系统导航返回。
- 光感按官方支持区域使用，避免给每条档案增加玻璃容器和循环动画。
- “减少动态效果”应覆盖新加动效；仍需接系统无障碍与省电策略，当前仅有应用内开关。
- 宽屏使用主从布局，窄屏使用栈；后续调整以窗口宽度而非设备型号判断。
- 阅读页正文优先可读性，不把字压在复杂背景上。内容图需真实、可授权、可离线。
- 至少覆盖 360vp、手机常规宽度、平板横竖屏、分屏、大字和深色。
- 光效必须检查真实设备能力、滚动帧率和点击反馈，不能用截图证明动态性能。

参考与已验证 API 见 `HARMONY_RESEARCH.md`。

## 10. 正式演示建议

五分钟视频建议顺序：

1. 30秒：五城和多维检索，打开准确的文化档案。
2. 60秒：离线查看图文，收藏、标签和笔记操作。
3. 90秒：两台设备登录同一账号，手机收藏或写下感受，平板自动显示个人信息及真实同步状态。
4. 60秒：设备离线时照常使用，恢复连接后同步新增/修改/删除；展示实际结果，不要求同时编辑同一笔记。
5. 40秒：关联推荐/专题档案，仅展示确实完成的功能。
6. 20秒：技术与价值收尾，整个视频不出现院校团队身份。

展示鸿蒙价值以同账号多设备的数据同步和自然使用为主，不引入团队协作、任务交接或多人同时编辑。沉浸光感是辅助体验亮点，不可代替题目核心能力。
