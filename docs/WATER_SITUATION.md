# 黄河水情：实时适配与成品化界面

## 1. 交付

首页五城河洛下方新增一张深青“河窗”卡，进入独立原生水情页。页面以“水面仪表盘”呈现实时水情：花园口为主站，可切换高村、利津；三站流量对照、两个短解释卡，界面不展示来源清单、URL、历史报道或免责声明。

| 项目 | 内容 |
|---|---|
| 主站 | 花园口（黄河下游 · 郑州北郊） |
| 可切换站 | 高村、利津 |
| 数据 | 2026-10-20 08:00：花园口 88.94 m / 911 m³/s；高村 57.38 / 816；利津 8.52 / 257 |
| 状态 | `实时 · 08:00` / `上次更新` / `离线数据` / `正在更新` |
| 入口 | 首页细卡，不新增底部 Tab |
| 刷新 | 主卡右上角原地刷新 |

## 2. 界面结构

1. **深青主卡**：黄河水情、状态点、更新时间、刷新按钮；站名 34 号字；水位、流量 30 号字；三站胶囊。
2. **三站对照**：横向流量条，选中站玫瑰色，其余青色；点击切换主卡。
3. **看懂水情**：水位、流量、含沙量三个短解释；含沙量本期未发布，不以 0 代替。
4. **为什么是花园口**：73 万 km² 控制流域、1938 年建站、悬河断面三个数字；一段两句解释。

界面刻意删去来源清单、公开报道卡片、长免责声明和“资料说明”，把空间留给数字、对照与阅读节奏；离线时只用状态文字和刷新按钮，不弹警告框。

## 3. 数据与实现

- 源站：黄河水利委员会“黄河实时水情”公开页面（IP + 明文 HTTP + ASP.NET）。服务端跟随 302、保留 Cookie，解析河名 / 站名 / 时间 / 水位 / 流量 5 列；当前页面不提供含沙量，统一 `null`。
- 服务端：`server/water-situation.mjs` 抓取、解析、10 分钟缓存；`GET /water/situation` 公开只读，失败返回上次快照并标记 `stale`。
- App：`WaterSituationClient` 读取自有 HTTPS 接口；首页与水情页共享同一组实时值。首次失败使用内置花园口离线值，刷新失败保留上次成功值。
- 边界：抓取不进入 HAP；不做七日趋势、全站可视化、洪水预测或防灾指令。源站页面改版时靠缓存与离线状态兜底。

数据源地址与字段说明参考社区项目 [Daily-Yellow-River-Information-Download](https://github.com/944568752/Daily-Yellow-River-Information-Download) 的公开 README，未复用其代码。

## 5. 未覆盖

- 近七日趋势、全站选择与服务端按日留存。
- 源站为 IP + HTTP + ASP.NET，页面结构变化会导致解析失败；缓存与离线状态可兜底，但不能承诺长期实时。
- 22 页校赛设计文档 9.1 节仍把水情写成“下一阶段”，提交前需要补一页或同步该节。
