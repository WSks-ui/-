# 黄河水情观察 v1：服务端实时适配 + 公开报道回退

## 1. 交付范围

校赛包新增一条从首页进入的原生“黄河水情观察”页面。v1 通过服务端抓取黄委“黄河实时水情”当天表格，App 只读自有 HTTPS 接口；抓取失败时回退到内置的三条公开报道摘录。页面不提供洪水预测或防灾指令。

| 项目 | v1 范围 | 不在 v1 |
|---|---|---|
| 代表站 | 页面展示花园口、高村、利津；接口返回当天 16 个站 | 全站可视化、历史多日选择 |
| 数据 | 黄委“黄河实时水情”当天表格：河名、站名、时间、水位、流量 | 含沙量（当前页面不提供）、近 7 日趋势 |
| 更新 | 服务端抓取，10 分钟内存/磁盘缓存；`stale` 标记上次快照 | 定时推送、WebSocket、实时报汛承诺 |
| 回退 | 三条公开报道（央广网 / 黄委 / 封面新闻） | 用假数据补缺测 |
| 入口 | 首页五城河洛下方细卡，不新增底部 Tab | 独立底部主入口 |

## 2. 数据源与字段

- 源站：水利部黄河水利委员会“黄河实时水情”公开页面  
  `http://61.163.88.227:8006/hwsq2.aspx?sr=0nkRxv6s9CTRMlwRgmfFF6jTpJPtAv87`
- 页面为 **IP + 明文 HTTP + ASP.NET WebForms**：首次请求 302 到 `default.aspx` 并种 Cookie，再跳回 `hwsq2`；服务端手动跟随重定向并保留 Cookie。
- 当前表头为 **河名 / 站名 / 时间 / 水位 / 流量**，5 列；**不提供含沙量**，统一为 `null`，不用 0 代替。
- 2026-10-20 08:00 实测：

| 站名 | 水位 | 流量 |
|---|---|---|
| 花园口 | 88.94 m | 911 m³/s |
| 高村 | 57.38 m | 816 m³/s |
| 利津 | 8.52 m | 257 m³/s |

页面首屏、首页细卡和截图均使用这一组当天数据，不再是 2026-09-21 的 88.42 m / 607 m³/s。

**参考与边界**：数据源地址与字段说明参考了社区项目 [Daily-Yellow-River-Information-Download](https://github.com/944568752/Daily-Yellow-River-Information-Download) 的公开 README；没有复用其代码或硬编码解析状态。该页面 2024 年改版后只稳定提供当天表格，页面结构一变，服务端解析就会失败并回退，不能把“抓取成功”当成长期保证。

## 3. 架构与实现

| 层 | 文件 | 说明 |
|---|---|---|
| 服务端抓取/解析 | `server/water-situation.mjs` | 302 + Cookie 跟随、5 列表格解析、日期拼接、10 分钟缓存、失败回退 |
| 服务端接口 | `server/account-service.mjs` | `GET /water/situation`，公开只读，不需要账号会话；返回 `stale` / `error` |
| App 客户端 | `entry/src/main/ets/sync/WaterSituationClient.ets` | 复用 Debug HTTPS 端点与自签证书，GET 接口并校验返回 |
| 领域模型 | `entry/src/main/ets/domain/WaterSituation.ts` | 实时回包、站点、空值、校验；公开报道回退模型 |
| 数据回退 | `entry/src/main/ets/data/WaterSituationCatalog.ts` | 三条公开报道与来源，断网/源站失败时使用 |
| 首页 | `entry/src/main/ets/pages/Index.ets` | 水情细卡，启动时读取实时值；显示“实时 / 上次快照 / 公开报道” |
| 页面 | `entry/src/main/ets/components/WaterSituationPage.ets` | 实时三站、来源、公开报道背景、流量对照、读水情、阅读边界 |

关键行为：

1. **服务端抓取**：`fetch` 手动跟随 302，保留 `Set-Cookie`；页面按 `<tr>` / `<td>` 解析 5 列，跳过表头与导航表。
2. **缓存与回退**：缓存写入 `.local/water-situation/snapshot.json`，10 分钟内直接返回；抓取失败返回上次快照并置 `stale=true, error='WATER_FETCH_FAILED'`；无缓存返回 503 与空站列表。
3. **App 状态**：页面与首页细卡显示“实时 / 上次快照 / 离线”；失败时仍展示三条公开报道，并明确“非实时”，不把回退值伪装成当前报汛。
4. **缺测不补**：某站流量为 `-` 时返回 `null`，页面显示“未给出”；含沙量当前页面没有，不生成数字。
5. **不带抓取进 HAP**：App 不直连 IP + HTTP 源站，避免明文、跨域和页面结构变化直接进入客户端。

## 4. 页面结构

1. **首屏**：`黄河实时水情` + `实时/上次快照` 状态；花园口；水位 88.94 m、流量 911 m³/s；观测时间与来源。
2. **今日实时水情**：花园口、高村、利津三行；来源 URL 可复制；失败时显示“上次缓存”提示。
3. **为什么先看花园口**：悬河断面、控制流域约 73 万 km²、1938 年设立的水文站。
4. **背景：三次公开报道**：2026-08-12 / 08-14 / 09-21 三条来源，缺测保持“未给出”。
5. **流量对照**：三次公开报道的相对比较；不画连续七日趋势。
6. **读水情 / 来源 / 阅读边界**：水位、流量、含沙量的读法；逐条来源；非实时、不提供预测或防灾指令。

## 6. 未覆盖与风险

- **近七日趋势**：当前源站只稳定提供当天表格，不做多日拼接；需要服务端按日留存并明确缺测。
- **多站全量**：接口返回 16 站，页面只展示花园口、高村、利津三个代表站。
- **源站稳定性**：IP + HTTP + ASP.NET，页面改版即解析失败；服务端有缓存与回退，但不能承诺实时可用。
- **1.5 倍字体 / 深色**：水情页尚未专项截图。
- **22 页校赛文档 9.1 节**：仍把水情写成“下一阶段、不放进校赛包”；v1 已落地实时适配，提交前应补一页或同步该节。
